# 音藏網站重審查證與證據界線

**日期**：2026-09-22

**用途**：支援本輪網站企劃重審。以下只引用官方原始資料；產品建議另行標示，不把競品規則直接當成音藏規則。

## 一 作品與版本分層已有成熟案例

Discogs 的 Master Release 聚合相符的發行版本；MusicBrainz 的 Release Group 也區分專輯概念與具體發行。這支持音藏沿用作品／版本分層，但不能以這個結構本身宣稱獨創或競爭優勢。

來源：[Discogs Master Release](https://support.discogs.com/hc/en-us/articles/360005055493-Database-Guidelines-16-Master-Release)、[MusicBrainz Release Group](https://musicbrainz.org/doc/Release_Group)。查閱日：2026-09-22。

**本案推論**：應驗證的差異是繁體中文辨識指引、選定收藏圈的資料完整度，以及非專家完成整理的成本。這些優勢尚未經使用者測試或資料覆蓋比較證實。

## 二 版本線索不能直接當成版本判決

Discogs 的一般規則要求不同發行能被辨認，並指出條碼或矩陣號不同未必代表需要新增發行；單件編號和部分製造差異也不直接構成獨立版本。

來源：[Discogs General Rules 第 1.4 節](https://support.discogs.com/hc/en-us/articles/360005006334-Database-Guidelines-1-General-Rules)。查閱日：2026-09-22。

**本案推論**：保留條碼、品號、包裝等線索，但採證據與可重複辨認的差異判定。無法確認時允許私人待辨認收藏，另設公共候選版本提案。特典、官方簽名批次及盒裝的具體邊界仍須用實物測試。

## 三 ISRC 應放在錄音資料的延伸層

IFPI 說明 ISRC 辨識錄音及音樂錄影，不是整張 CD 或其他產品的識別碼。一件多曲目發行不能只用單一 ISRC 當版本身分。

來源：[IFPI ISRC FAQ 第 24 題](https://isrc.ifpi.org/faqs)。查閱日：2026-09-22。

**本案建議**：第一版版本辨識不要求 ISRC。未來若收錄曲目及錄音關係，再把它掛到適當錄音資料；保留條碼與目錄號作為產品辨識線索，但也不把它們設為唯一可靠判定。

## 四 網址層級不保證搜尋排名

Google 說明網站連結與導覽會影響搜尋引擎理解內容關係；SEO 入門文件也指出網址路徑中的關鍵字本身對排名影響很小。巢狀路徑不能單憑形式保證「繼承作品權重」。

來源：[Google 網站結構說明](https://developers.google.com/search/docs/specialty/ecommerce/help-google-understand-your-ecommerce-site-structure)、[Google SEO 入門](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)、[Google 網址結構](https://developers.google.com/search/docs/crawling-indexing/url-structure)。查閱日：2026-09-22。

**本案建議**：先決定穩定識別碼、正式頁面、合併轉址和內部連結。作品與版本在畫面上維持清楚關係；版本網址是否巢狀應依更正及合併成本決定。真實資料、可辨識差異與來源才是內容規劃重點。

## 五 設計規範的大字門檻單位需更正

W3C 對比準則的一般文字門檻為 4.5:1，大字為 3:1。大字的常用門檻是 18pt 或粗體 14pt，約為 24 CSS px 或 18.67 CSS px；CJK 字型需考量等效大小。

來源：[W3C WCAG 2.2 Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。查閱日：2026-09-22。

**本案發現**：`網站/DESIGN.md` 寫成 18px／粗體 14px，單位不正確。這輪只記錄修正建議，未改設計檔或介面；也沒有因此宣稱現有配色不合格，實際合規仍須檢查各文字與背景組合。

## 六 尚無足夠證據的既有說法

| 說法 | 目前可支持的程度 | 需要補什麼 |
|---|---|---|
| 台灣音樂版本資料沒有地方收錄 | 原始使用經驗與初步觀察 | 選定作品逐一比較 Discogs、官方資料、其他資料庫及既有社群 |
| 版本比對是其他平台沒有的差異 | 尚未完成競品操作稽核 | 同一辨識任務的實際結果、正確率與耗時；不能只比較首頁 |
| 使用者會長期管理收藏 | 尚未觀察 | 真實整理後是否主動查找、修正、匯出或分享 |
| 先手填 5 件再 AI 代填 15 件可證明 AI 價值 | 可找流程問題，無法直接得出因果效果 | 任務難度、順序、熟悉度與協助者不同都會影響結果 |
| 建完再手填 2 件可以扣掉熟練影響 | 可觀察後段表現，不能直接扣除影響 | 保留原始紀錄；需要較公平比較時另做相近難度與不同順序測試 |
| 音樂公司會付費買資料 | 商業假設 | 有明確用途、願付價格與小規模付費驗證 |
| 每月 NT$1,400–5,000 足夠 | 舊估算，這輪未覆核價格 | 依當時供應商、實際流量、圖片與人工工作量重算 |
| 法律可行性已確認 | 未取得專業確認 | 由台灣律師確認圖片、資料權利、條款、個資及不同交易責任 |

以上「待查證」不等於已被否定。本次沒有全面競品普查、使用者研究、正式法務審查、供應商報價或 AI 主機實測。
