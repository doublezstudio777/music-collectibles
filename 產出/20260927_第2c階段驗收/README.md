## 本輪做了什麼

1. **2b 遺留**：`/img/` 全部回應加 `X-Content-Type-Options: nosniff`；申訴證據照片改放 `a/`，只給本人與管理員（其他人 404、`private, no-store`、不進快取），舊資料 purpose=appeal 的也一樣檢查
2. **維基式編輯**：系列正文、藝人簡介可編輯（已驗證 Email、修改說明必填、`baseId` 防同時編輯互蓋）；每次存一版（作者、時間、說明、字數變化）；頁面「最後修改：某某，日期 · 歷史」；歷史頁可選兩版比對（段落＋逐字差異）、還原（新增一版）、管理員鎖定／解除；維基來源的簡介每一版都標 CC BY-SA 4.0
3. **熱門藝人與藝人目錄**：名字連藝人頁、追蹤、不感興趣（存 D1，下一位補上）、最後一格「看全部藝人」；`/artists` 男歌手／女歌手／團體 × 國內／國外篩選；`GET /api/artists`
4. **歷史價格**：成交寫 `deals`、改回出售中作廢；版本區塊「成交行情」：近期成交區間、中間值、SVG 走勢、目前開價與出價區間；方法見技術設計第十九節；`GET /api/prices`
5. **管理員下架**：隱藏／恢復五種對象、永久刪除只限空頁面（擋下時列原因、刪前存快照、系列號不重用）、藝人頁自動顯示規則＋強制開關；後台「下架」區塊
6. **寄信接 Resend**：有 `RESEND_API_KEY` 走 Resend，沒有印 console；寄件人 `音藏 <noreply@notify.dblzm.com>`、Reply-To `zukawork0312@gmail.com`；信件只有驗證碼＋一句說明
7. **零花費三層防線**：①8GB 容量上限仍生效（2b 的 `reserveBytes`，5c 暫停時上傳 503 同一條路）②照片每月讀取計數（Cache API 沒中才讀 R2 並計數、每 20 次寫一次 D1、800 萬次改佔位圖）③webhook `POST /api/internal/budget-alert` 驗 `cf-webhook-auth` 共用密鑰 → 暫停模式，後台可解除
8. **不給搜尋引擎收錄**：meta noindex＋`X-Robots-Tag: noindex`，`ALLOW_INDEXING` 一次打開；robots.txt 依主對話修正改為允許爬取、只擋 `/admin`、`/api/`；單則炫收藏補 Open Graph
9. **備份**：`scripts/backup.mjs`（`.sh`／`.bat`）、`scripts/restore.mjs`；Time Travel 說明與來源寫進技術設計第二十二節與部署手冊

## 已知問題與取捨

1. **預算通知接不上 webhook**：Cloudflare 通知的 webhook 要帳號有 Pro 以上方案的網域才能用，音藏是免費方案。端點做好了、本機驗過，但 Cloudflare 那端目前只能寄信。部署手冊第六節給了 Google Apps Script 讀信打 webhook 的免費做法，要使用者決定
2. **PBKDF2 10 萬次很可能超過免費方案 10ms CPU**：本機 Node 12.3ms。做成環境變數可調（10,000～100,000），部署後實測；調低不用改程式，舊密碼下次登入自動換新次數。安全性會下降，靠 Turnstile＋登入頻率限制補
3. **讀取計數會少算**：為了省 D1 寫入，每個 Worker 執行個體累積 20 次才寫一次，執行個體被回收時沒寫進去的就丟了。門檻設在免費額度 80% 留緩衝；要精準得改讀 Cloudflare 的 R2 分析 API（要 API 權杖），這輪沒做
4. **Cache API 在 workers.dev 的實際命中率沒實測**：本機 Miniflare 行為不一定跟正式一樣。沒命中只是多算讀取次數（多耗免費額度），不會多花錢；部署後看「本月照片讀取」的成長速度判斷
5. **歷史價格只算有選版本的收藏**：沒選版本（「不確定版本」）的成交不進行情；成交當下雙方是誰、後來刪帳號怎麼算，等刪除帳號策略定案再處理
6. **歷史價格的「認證帳號」是計算當下的狀態**：某人事後被取消驗證，他以前的成交就不算（3g 驗的就是這個），這是刻意的
7. **隱藏的炫收藏，照片網址本身仍打得開**：頁面、牆、API 都看不到，但知道 `/img/p/…` 網址的人仍能讀照片（檔名是隨機 id，猜不到）。要連照片一起擋，得在 `/img/` 多查一次那則有沒有被隱藏
8. **永久刪除的判斷偏嚴**：只要有人按過「我有／想要」、有檢舉紀錄、或任何炫收藏提到這位藝人，就不能刪，只能隱藏。寧可多擋，免得刪掉後網址被重用、別人的紀錄指到新內容
9. **藝人頁自動顯示看的是「前台看得到的內容」**：系列全被隱藏、收藏全被隱藏的藝人也會跟著 404；要保留就用強制顯示
10. **熱門藝人「不感興趣」要登入**：訪客按了會跳登入小面板（localStorage 已停用，不另存訪客狀態）
11. **維基式編輯目前只有純文字段落**：沒有連結、粗體、圖片；空一行分段。系列的其他欄位（年份、品項、版本資料）仍走「這裡沒有，我要新增」與待審核，不在這次的維基編輯範圍
12. **歷史頁的時間顯示台灣時間**，資料庫仍存 UTC；後台操作紀錄順手改成台灣時間（2b 原本顯示 UTC）
13. **信件內容改了一句**：驗證信從「你的音藏驗證碼是 123456」改成「音藏驗證碼：123456」＋一句說明。2b 的驗收腳本用舊句子抓碼，重跑 2b 腳本要改正規式（2c 腳本已用新句子）
14. **備份的照片不按日期重複存**：D1 每次一個日期資料夾；照片累積在 `R2-remote/`，manifest 記下每次新增的檔案。照片內容不會改，重複存只會把 OneDrive 塞滿
15. **`wrangler d1 export` 的 SQL 不能直接還原**：子表排在 `users` 前面，直接執行會撞 `no such table: main.users`（本輪實測）。所以另寫 `restore.mjs` 重排語句；只准還原到新的空資料庫
16. **`d1 export` 本機只讀 `.wrangler/state`**：`backup.mjs --local` 不支援其他資料夾，所以「從空資料庫套遷移」用 `--persist-to` 暫存資料夾，「還原演練」也是還原到暫存資料夾
17. **炫收藏表單的系列名稱範例字「例：夜行採集」是示範資料裡的虛構專輯**：只是 placeholder，會打包進正式版，不影響資料；要換成真的例子再說
18. **本機驗收資料都留著**（測試資料只在本機 D1，正式資料庫仍是空的）：驗收帳號、成交、隱藏紀錄都在 `網站/.wrangler/state`，本機示範資料因此多了驗收產生的炫收藏與歷史版本
