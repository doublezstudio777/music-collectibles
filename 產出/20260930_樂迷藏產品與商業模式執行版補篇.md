# 樂迷藏：產品與商業模式執行版補篇

**版本**：2026-09-30，第一版

**用途**：接在原始 17 章企劃書之後，作為目前網站的執行判斷依據。原書保留當時的推理與歷史版本；兩份內容衝突時，已由使用者後續定案的方向及本補篇的現況判斷優先。這份文件不授權新的網站功能或部署。

**證據界線**：現況取自截至 9/30 的共用交接、決策文件、網站程式與驗收紀錄。本輪未查正式站資料庫、帳單、訪客行為或實際營收。因此「功能已上線」「資料已匯入」與「需求已成立」分開寫。

## 1. 現在要做的是什麼

樂迷藏讓人**看見別人的音樂收藏、分享自己的實物，並沿著藝人、作品、版本、活動與主題查懂其來歷**。有人願意提供照片、來源及修正，才可能逐步形成可信的公共收藏資料。對想買賣的人，站上可以表達出售與出價意願；目前成交後由雙方自行約面交或轉帳，平台不經手錢貨。

這個順序是產品與營運的共同判準：先看是否有值得看的真實收藏，再看是否有人願意分享和補證據，接著才看撮合是否自然發生。首頁、藝人資料和版本資料都應幫人完成上述事情。歌曲推薦是藝人探索入口，其價值要用它是否帶人進入收藏與藝人內容來判斷。

平台使命保留使用者 9/26 的原意：把分散在收藏者手上的實物與知識累積成更完整的資料，降低版本不明與仿冒造成的風險。**資料庫能輔助辨認，不對單件商品、賣家或交易作保證。**

## 2. 哪些是決策，哪些仍是問題

| 層級 | 截至 9/30 的狀態 |
|---|---|

原企劃的「50–100 名核心測試者」「至少 30 人建立願望清單」「四週 25% 回訪」是當時研究型 MVP 的目標，不應直接套到已改為分享優先、且測試站仍 noindex 的現況。新版先取得基線，再訂擴大招募的量化目標。

## 3. 使用者與他們要完成的事

| 對象 | 第一次想做的事 | 有理由回來的條件 | 平台要付出的成本 |
|---|---|---|---|
| 瀏覽的樂迷 | 找到某位藝人或一件有故事的收藏 | 內容持續增加，能沿藝人、標籤及版本找到新東西 | 導覽、內容品質、照片與來源管理 |
| 分享實物的人 | 放上照片與故事，被懂的人看見 | 分享過程輕、有人互動，自己的收藏能和正確資料相連 | 上傳、私隱、下架、社群審核 |
| 懂版本的貢獻者 | 更正錯誤、補充來源或辨識線索 | 修改可追溯、署名清楚、爭議有處理方式 | 資料校對、修訂與申訴 |
| 想買賣的人 | 找到願意談的對象、確認正在談哪一版 | 資訊清楚、聯絡有效、風險說明誠實 | 檢舉、防詐、客服與爭議處理 |
| 唱片行等專業賣家 | 展示可辨識的庫存與建立信任 | 上架／維護比現有做法省事，且真的帶來合適詢問 | 帳號核實、店家工具、獨立審核 |
| 發行方與活動單位 | 了解收藏者關心哪些實物與版本 | 資料可追溯、案例有價值、合作方式清楚 | 授權、合作管理、研究與交付 |

前四類是目前要先觀察的人。專業賣家和發行方的付費機會須用個別訪談或小合作驗證，不能只從站內收藏數推論。

## 4. 現行核心流程與應守住的區別

1. **觀看**：免登入看到分享牆，進入一則真實收藏，沿藝人、作品、版本或主題看更多內容。點讚加入喜愛清單，不表示持有或發文。
2. **分享**：登入後以實物照片和描述建立自己的炫收藏；可用自由標籤與現有資料連結。版本還不確定時，可以先分享、保留待辨認。公開發文與「我有」是不同資料與不同承諾。
3. **辨識**：收藏者或編輯提出系列／版本、曲目、實物特徵和來源；修改留下紀錄，錯誤可更正。外部匯入資料、實拍佐證、自訂標籤及平台已審查關係要能分辨。
4. **撮合**：發文者可選純分享、開放出價或定價出售；有意購買者在站內提出意願與聯絡。開價、出價、接受、雙方自願回報已售出是不同事件；平台沒有收款、出貨與真偽保證。

場刊或活動手冊是獨立收藏品；其中列出一位藝人的名字、介紹他、記錄演出或記錄獲獎，是不同關係。合輯只在確有發行及收錄證據時建檔，不能由入圍名單自動生成。這些關係既影響可信度，也影響之後搜尋與合作的價值。

## 5. 目前的商業模式

| 要素 | 執行版 |
|---|---|
| 核心價值 | 真實收藏展示、音樂實物的版本脈絡、可追溯的共同補充與更正；撮合為延伸情境。 |
| 供給來源 | 樂迷的公開分享與照片、可引用的既有音樂資料、經來源確認的編輯、實際存在的收藏品。外部匯入量與實物佐證量分別衡量。 |
| 需求來源 | 想看收藏與故事的樂迷、查版本的人、想買賣的人；店家和官方在證明價值後再納入。 |
| 接觸方式 | 站內藝人／版本／標籤探索、收藏者對外分享連結、定向邀請樂迷。測試站仍 noindex，現階段不把搜尋流量當主要成長來源。 |
| 維持關係 | 讓分享者看見作品被理解，讓資料貢獻可署名與更正，讓檢舉有回應；不以昂貴藏品排行作地位核心。 |
| 必要能力 | 資料來源治理、內容審核、版本關係、照片保護、備份、客服、社群招募與觀察。 |
| 合作對象 | 第一批是願意分享或校對的收藏者；店家、發行方、活動單位與律師是依階段加入的合作對象。 |
| 成本 | 主機、儲存、郵件、備份、網域與可能的第三方服務；站長花在招募、核對、檢舉、申訴和客服的時間。 |
| 收入 | 贊助、專業店家可付費的具體服務、日後第三方金流交易服務、發行方的商品或內容合作；皆須逐階段驗證。 |

## 6. 收入路線：保留順序，設啟動條件

| 階段 | 目前狀態 | 必須先看到的證據 | 不應承諾的事 |
|---|---|---|---|
| 站長贊助 | 已決定要提供；網站有頁尾入口機制，但未設收款連結時不顯示，無可確認收入 | 有人自主贊助、款項可核對，文案不干擾閱讀與信任 | 贊助足以負擔固定成本；贊助者影響資料判定 |
| 店家服務 | 前期可免費參與，收費方式未定 | 店家能穩定提供可辨識庫存與回應；至少一項工具或服務讓店家願意付費，且一般會員仍可正常分享 | 付費標章代表真品保證；只因店家有帳號就能收費 |
| 交易服務 | 目前只撮合，錢貨在站外；日後才考慮第三方金流 | 多次可確認的有效配對、買賣雙方願意在站內完成額外步驟，以及金流、糾紛與營運成本可承擔 | 以開價或單方「已售出」估算可抽成成交額 |
| 官方合作 | 合作內容尚未定案、沒有可確認採購 | 具體對象提出明確問題，平台能交付有來源、權限和用途界線的內容／企劃／商品合作，並實際簽約付費 | 把會員原始行為或個人資料直接「賣給官方」；把小樣本當市場銷量 |

原書的精準廣告及匿名市場洞察保留為遠期候選，不列入近期收入預算。若未來測試，先說清楚廣告如何標示、資料是否有代表性、使用者同意與再辨識風險；相關法律問題交專業人士確認。

## 7. 信任規則就是產品規則

- **資料收錄**表示站上有此條目及其來源，未必表示官方或平台確認每一個版本細節。
- **實物照片**表示會員曾上傳該影像；浮水印與查證碼可幫助辨認站內發布來源與下架狀態，不能證明現在仍持有、物件是真品或賣家會履約。
- **標籤與關係**分開：使用者可以自訂話題；客串、曲目收錄、場刊列名、入圍及得獎要有各自的對象與來源。錯誤能提報、修正並保留紀錄。
- **照片與辨識資訊權限**須兼顧公開查知識和防盜用。目前大圖及部分辨識細節需要登入；先測樂迷能否完成查詢、受限資訊是否真有降低濫用的效果，再決定是否調整。
- **交易事件**只描述站內能看見的行為；站外付款、寄送與實際收到貨若無可靠回報，維持未知。對外價格資訊須分清開價、出價、雙方回報與可驗證成交。

站名、收錄範圍、照片授權、內容下架、個資與可能的店家權利義務，正式擴大營運前仍需台灣專業律師審閱。本補篇不作法律結論。

## 8. 下一個工作段落：用現有網站驗證

### 8.1 先記基線，避免把測試資料算進去

不用先增加功能。從既有後台、備份報表和自願參與者紀錄一次性整理：

| 指標 | 定義與分母 | 目前基線 |
|---|---|---|
| 公開內容供給 | 非測試帳號發出的有效炫收藏、獨立分享者、附實拍與可辨認物件者；按品類分開 | 待量 |
| 資料證據 | 版本條目中有來源、有實物佐證、有待確認關係者的數量；匯入與會員貢獻分開 | 待量 |
| 觀看 | 受邀訪客進入分享與藝人／版本頁、完成指定查找任務的人數；不以頁面總請求數代替人 | 待量 |
| 發布 | 願意開始表單、完成發布、七天內自主補充或再發者；記錄時間與協助量 | 待量 |
| 撮合 | 有效詢問、回覆、接受、撤回、雙方自願回報成交；出價與成交各自計數 | 待量 |
| 現金與工時 | 每月帳單及站長每週招募、審核、校對、客服、修復工時 | 待量 |

沒有現成事件資料時，用受邀者的操作觀察與訪談補足，不能把估算寫成正式站統計；任何新增追蹤都需另行評估必要性、告知及實作。

### 8.2 小群體試用，不追求代表全市場

先邀 **5–8 位**角色不同的樂迷，可一人兼多種角色，但記錄角色：有人只想看、有人有實物想分享、有人懂版本、有人真的想找或出售。以真實物件執行四個任務：從首頁找到值得看的收藏；自己發一件唱片或場刊；核對一件有版本差異的物件；若本人確有買賣意願，再觀察詢問流程。不要製造假交易。

每個任務記錄是否獨立完成、卡住的位置、理解錯誤、是否需站長代填、所需時間、願不願再使用，以及受訪者原話。第一天後約一週及四週各追蹤一次：有沒有在沒有提醒下回來、再次分享、補資料或聯絡對方。受訪者願意給的回饋和實際操作分開記，不能只看「覺得不錯」。

### 8.3 在試用前寫好判讀規則

| 要驗證的假設 | 看到什麼可以繼續 | 看到什麼就調整 |
|---|---|---|
| 看別人的收藏有獨立價值 | 受訪者能自行找到感興趣內容，說得出想再看的理由，且有人自發回訪 | 只停留在歌曲播放器，找不到真實收藏或覺得內容太少：先補可看的收藏與導覽，不急著加藝人或版本數 |
| 分享負擔可承受 | 分享者能以自己的照片與故事完成發布，事後願意補充或再發 | 主要靠站長代填，卡在版本判定或照片：縮短首發必填、改善後續補資料流程 |
| 資料能幫助辨認 | 懂版本者可用來源與實物特徵判別，能指出錯誤並完成更正 | 匯入資料常被誤讀為已驗真，或客串／場刊／獎項歸屬錯：先治理來源和關係，再擴匯入 |
| 撮合有價值 | 有真實買賣雙方建立有效聯絡，雙方理解平台的能力邊界 | 只有瀏覽或隨手出價、沒有可確認後續：維持免費撮合，不估交易收入 |
| 收入服務值得做 | 贊助有實際收款；店家或官方說出具體可付款問題並願意試小案 | 只有口頭好評、沒有明確工作或預算：收入繼續列假設，不投入專用系統 |

小樣本只用來發現阻礙與修正方向，不拿來宣稱全市場轉換率。原書的 8–12 週決策時鐘不必從網站部署日開始；在受邀者真正開始使用且基線定義完成時再記觀察期間。

## 9. 內容與功能的下一步排序

1. **先完成基線與小群體試用**：使用現成網站與資料，避免再由工程完成度決定優先序。
2. **補真正可看的內容與關係正確性**：若首頁供給不足，優先邀收藏者發真實內容，挑唱片、場刊與周邊各數件驗證分類；若資料有錯，修來源與角色關係。
3. **只修阻斷核心任務的介面問題**：例如訪客找不到分享牆、分享者必填過重、藝人頁把客串算主作品、場刊只剩模糊標籤。是否調整歌曲推薦的位置，由實際使用觀察決定。
4. **再考慮分發與擴大**：內容品質、權利處理、備份與回應能力穩定後，才討論解除 noindex、擴大邀請、店家工具或自動化匯入。

既有 9/30 四項待使用者決定的資料匯入與首頁「今天」提案仍是獨立待辦。本補篇沒有替使用者作答，也不阻止修復已發現的錯誤。

## 10. 成本帳與決策檢查點

每月記兩本帳。**現金帳**：網域、Cloudflare 各項實際收費、圖片儲存與傳輸、郵件、備份、工具或外包；公司代付也列成本。**時間帳**：招募、研究、建檔／校對、檢舉申訴、客服、技術維護，以小時及案件數記錄。原書 NT$1,400–5,000／月是未覆核舊估算，不能作現行預算或收支平衡點。

每完成一次試用與一輪回訪，作一次小決策：

- **繼續投入同一路徑**：有人自發看與分享、資料錯誤能被修正、站長處理量可承受。下一輪才擴內容或使用者。
- **調整入口或資料流程**：有興趣但找不到內容、發文負擔過重、外部匯入讓人誤解可信度。先解阻礙，不以新功能掩蓋。
- **縮小內容範圍**：只有特定藝人、年代或物件類型有穩定參與，就先在那裡做好關係與來源。
- **延後商業化**：有使用但沒有店家付費或有效撮合，維持低成本與自願贊助，不用想像中的抽成撐預算。
- **暫停擴大招募**：照片權利、資料錯誤、檢舉或站長工時已超出可處理能力，先處理信任與營運。

## 12. 尚待確認與不可偷換的結論

目前沒有足夠證據判定「樂迷會定期回來」「收藏者會自行補齊版本」「交易能產生可收費服務」或「官方會採購資料」。也尚未獨立核對正式站實際會員、活躍與收入。這些不是企劃的缺點，而是下一段工作要得到的答案。

**可立即採用的工作方向**：先記基線、用真實收藏執行小群體試用、保留更正與信任邊界、按觀察結果排下一批工作。使用者已同意按 9/30 偏差評估建立這份執行版；本文中的個別測試數量、判讀方式及未來收費條件是執行建議，尚非使用者逐項核定的產品規格。
