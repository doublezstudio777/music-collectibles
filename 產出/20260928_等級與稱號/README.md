### 「極小修改」判準

1. 把修改前、修改後的整頁內容各自接起來，去掉所有空白、標點與符號（Unicode 的 P、S 類，含全形逗號句號、引號、括號、驚嘆號、表情符號）
2. 兩邊去掉相同的開頭與相同的結尾，剩下比較長的那一段的字數，就是「改了幾個字」
3. **不到 10 個字＝極小修改，0 分**。只改標點、空白一律是 0 字；10～199 字 +20；200 字以上 +30
4. 同一人在同一頁連續編輯（中間沒有別人改、每次間隔 60 分鐘內）併成一次，以「第一次改之前 → 最後一次改完」的總改動算分，拆成很多小改動拿不到比較多分
5. 按「還原」本身不給分

第 2 步不做逐字比對（免費方案 CPU 上限 10ms，兩萬字逐字比對會超過），散在頭尾兩處的小修改會被算成中間整段，偏多不偏少。

### 「7 天內被還原」判準

編輯（或一輪連續編輯）最後一次改完後 7 天內，同一頁出現一筆修改，內容等於這次編輯之前的版本，或是還原到比這次編輯更早的版本，這筆編輯就不給分。7 天後才被還原，分數保留。

### 「檢舉成立」判準

- 收藏、品項、版本：管理員「維持鎖定」、或檢舉人數達門檻且沒被解鎖、或收藏被管理員下架。成立時間分別是裁決時間、第 N 位檢舉的時間、下架時間
- 留言：被檢舉自動隱藏且管理員沒恢復、或被管理員刪除
- 成立後 7 天內被申訴翻案（管理員解鎖、恢復留言），+10 作廢、改 −5；達門檻之後才跟上檢舉的人不加分，被翻案時一樣 −5

### 防刷分

- 內容被檢舉成立、被隱藏、被刪除：那筆分數作廢，已入帳的也扣回。取消讚、刪留言、成交作廢同樣扣回
- 每日上限以「全部事件」排名：被刪掉的那則仍佔名額，不會由超額的下一則遞補，扣回才扣得到
- 同兩個帳號之間：互讚（兩個方向合計）最多計 20 次、互留言合計最多 10 則、成交每人最多 2 筆有分
- 互留言的 10 則上限，留言者的「留言」與作者的「收到留言」一起算：第 11 則起兩邊都不給。收到留言的「每則收藏 50 則」另外算

### 停權：分數保留、停權期間凍結

- **不歸零**。停權中的會員分數照常保留、照常顯示在後台（前台個人頁本來就不給看）
- **凍結**：事件發生時間落在停權期間的一律不計，原因記為 `suspended`。例如停權中別人讚了他的收藏、他的檢舉在停權中被判成立，這些都不算；停權前已經發生、停權中才滿 7 天入帳的照常入帳
- **恢復後照常**：恢復之後發生的事件照常算分
- 停權期間靠 `suspensions` 表記（開始、結束時間），不是看帳號現在的狀態，所以恢復之後回頭重算，停權那段仍然不計
- 舊規則「按讚者被停權，他給的讚扣回對方的收到讚」**取消**：對方被停權不影響自己已經拿到的分數
- 舊規則「停權總分顯示 0」**取消**
- **分身刷分不再有特例（2026-09-28 更正）**：對方停權原因不管是什麼，他給的讚、留言、跟他的成交都照算，跟其他停權原因一視同仁（使用者原話：「我是覺得他真的要刷就給他刷吧」）。停權原因下拉選單仍保留「分身刷分」這個選項，只是選了不再影響對方的計分。曾經做過的 `peer_sockpuppet` 特例已拿掉；其他防刷規則（每日上限、同兩帳號互動上限、7 天入帳、還原不給分、被檢舉成立扣回）不動

### 補上缺漏資料：可以補的欄位

原本空白、補上後資料更完整的欄位都算，只能補空白的，補過的不能再補（409）。清單只在 `網站/lib/fill.ts` 一處。

| 對象 | 欄位 | 在哪裡補 | 什麼算空白 |
|---|---|---|---|
| 系列 | 發行年 | 系列頁標題下「發行年待補」 | 不是四位數年份 |
| 版本 | 發行年 | 系列頁每個版本區塊的「待補」 | 不是四位數年份 |
| 版本 | 地區 | 同上 | 空白、「—」、「待查證」 |
| 版本 | 發行（發行單位） | 同上 | 同上 |
| 版本 | 包裝 | 同上 | 同上 |
| 版本 | 內容物 | 同上 | 同上 |
| 版本 | 曲目 | 同上 | 同上 |
| 版本 | 目錄號 | 登入後「正版辨識」區塊的「待補」 | 同上（預設值是「待查證」） |
| 版本 | 辨識特徵 | 同上 | 同上 |

不算的：條碼（預設值「無條碼」分不出是沒填還是真的沒有條碼）、資料狀態（管理員判定，不算缺漏）、藝人的性別與地區（前台沒有顯示這兩欄，補了看不到）。

目錄號、辨識特徵屬於辨識細節，公開頁面（訪客與會員同一份快取）不放，只在登入後向 `/api/details` 取資料時一起顯示「待補」。

### 停權原因

- 後台會員頁按「停權」後要先選原因：詐騙、販售盜版、分身刷分、洗版或騷擾、其他，再加說明；選「其他」時說明必填。沒選原因送不出去（API 也擋，400）
- 寫進 `admin_log`（`{ reason: "分身刷分：說明", code, note }`）與 `suspensions` 表；會員列表「狀態」欄在「停權」底下顯示原因與說明
- 上線前就停權的帳號，遷移時補一筆停權紀錄（原因「其他」，說明取最近一次停權操作紀錄）。正式站目前沒有停權中的帳號，補了 0 筆

### 管理員指定等級

- 後台會員頁新增「等級」欄：顯示目前等級與分數；按「指定等級」選稱號＋Lv（25 級下拉選單），原因必填，寫 `admin_log`「指定等級」（含改之前的等級）
- 指定後全站顯示指定的等級（個人頁、留言、出價列表、資料貢獻者），分數照常累計；個人頁「離下一級還差」用指定等級的下一級算，分數已經超過就不顯示這句
- 「取消指定」回到計算值，寫 `admin_log`「取消指定等級」
- 會員自己看到的就是那個等級，前台不標示「指定」；只有後台列表標「指定（計算值 N 分）」
- 存在新表 `level_overrides`（沒有內容版本觸發器），指定的等級在整頁快取的頁面跟分數一樣最多舊 5 分鐘

## 計分怎麼跑

- 每一筆加減分是 `score_events` 一列（事件表）。按讚、留言、發文、成交、檢舉在動作當下**不寫任何計分資料**，每日排程從原始資料表補出事件；只有「編輯頁面」與「補上缺漏資料」在動作當下記一筆（要算改了幾個字、記誰補的）
- 每天台灣凌晨 2 點跟清理過期紀錄同一個 Cron 跑一次彙總：補事件、重算每筆狀態（待入帳／已入帳／作廢＋原因）、加總到 `user_scores`、更新稱號 `user_titles`。全部是一次 D1 batch 裡的 SQL，Worker 端只組字串
- 管理員另有 `POST /api/admin/scores` 可手動重算（本機可帶 `now` 模擬未來時間，正式站不收這個參數）
- 個人頁顯示「分數統計於 2026-09-28 02:00（每天統計一次）」，本人另外看得到「另有 N 分待入帳」
- 計分三張表、停權紀錄與指定等級兩張表都沒有內容版本觸發器。暱稱旁的等級在整頁快取的頁面（系列頁貢獻者、單則頁出價列表）最多跟著快取舊 5 分鐘；留言走 `/api/comments`、個人頁不快取，都是最新的
