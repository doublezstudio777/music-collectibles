## 做了什麼

**表單**（`components/photo-picker.tsx`，發文表單與編輯共用）
- `multiple`，可以一次選多張，也可以分次再加；滿 10 張選檔按鈕收起來，超過的顯示「一則最多 10 張，有 N 張沒加進來」
- 換順序：直接拖曳（滑鼠按住移動 4px 開始；手指長按 350ms 才開始，沒長按就滑＝捲動頁面），另有往前、往後、設封面按鈕。拖到第一格的那張立刻標「封面」
- 每張照片各自壓縮上傳（主圖長邊 1600、縮圖 480，規格沒變），同時最多 2 張；每格顯示等待中／上傳中，下方顯示「上傳中 X／Y」
- 單張失敗顯示原因與「重試」，只重傳那一張
- 刪掉還沒發布的照片會呼叫 `DELETE /api/uploads?id=`，R2 檔一起刪、容量扣回，不留孤兒檔；上傳途中被刪的，傳完就刪
- 預覽圖（1200×630、燒進浮水印）只在送出時替封面畫一張，走新的 `POST /api/uploads/og`

**限制與計數**
- 每日 30 張：原本就是每張上傳各算一次，多張之後照樣每張算一張；預覽圖不算張數
- 8GB 容量：每張主圖＋縮圖（＋封面預覽圖）都先佔額度；刪照片、拿掉舊封面預覽圖都扣回
- 伺服器端：發文與編輯都擋超過 10 張（400 `TOO_MANY_PHOTOS`），0 張回「至少放一張照片」

**單則頁**
- 封面放大，下面一排縮圖，點了切換；大圖區用 scroll-snap，手機可以左右滑，右下角顯示第幾張
- 點照片開大圖檢視器，多張時有上一張、下一張、方向鍵、手機左右滑
- 分級沿用 `/img/` 每個檔各自判斷：未登入只有縮圖，主圖 401；登入才拿得到 1600px
- 商品卡、og:image 仍然只用封面。全部照片的清單只放在單則頁（`toDetailView`），首頁與列表的 HTML 不帶其他張的網址

**編輯既有炫收藏**（單則頁作者看得到「編輯照片」）
- 補照片、刪照片、換封面、調順序，存檔走 `PUT /api/shares/{n}/photos`（整份新順序）
- 刪掉的照片：R2 主圖、縮圖、預覽圖刪檔，D1 標 `deleted_at`，容量扣回，快取清掉
- 封面換掉才重畫預覽圖：舊封面的預覽圖從 R2 刪掉，新封面用主圖在瀏覽器重畫一張；只調順序、封面沒換就不動
- 被鎖定（檢舉達門檻等）或隱藏的收藏不能改照片，照片可能是檢舉證據

**隱藏、刪除、檢舉**：原本就是以「收藏底下每一列 photos」為單位處理，`/img/` 查 D1 時照片跟著所屬收藏判斷，隱藏後每一張（含預覽圖）都 404；`purgeSharePhotos` 清的是這則所有照片的主圖、縮圖、預覽圖。刪帳流程以會員的所有照片為單位，也涵蓋多張。

## 已知問題與取捨

1. 拖曳是「拖到哪格就即時換位」，沒有另外做跟著手指走的浮動縮圖；被拖的那格有外框加半透明標示
2. 上傳進度以張數顯示（上傳中 X／Y），沒有單張的位元組百分比（fetch 拿不到上傳進度，要改 XHR）
3. 送出時封面預覽圖畫失敗（極少見，例如字型沒載到）不擋發文，og:image 退回封面縮圖，跟原本單張時的處理一樣
4. 編輯換封面時，新封面預覽圖是存檔後才畫；這一步失敗同樣退回縮圖，下次換封面會再畫
5. 表單裡選了照片但沒送出就離開頁面，已上傳的照片會留在 R2（沒有掛到任何收藏）。單張時代就有這個情況，容量有算進去，沒有另外做排程清理
