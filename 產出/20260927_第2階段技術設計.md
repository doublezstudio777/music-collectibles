## 三、資料表

### 識別碼原則

- 使用者：隨機字串 `users.id`（不外露註冊順序），公開網址用 `handle`
- 內容沿用現在的公開網址當穩定識別碼：炫收藏流水號 `share_no`（`/share/{n}`）、藝人 `slug`、系列 `{slug}/{流水號}`、版本鍵 `{slug}/{流水號}#{品項}-{版本}`。**slug 一經建立不改**；藝人改名只改顯示名稱，要換網址另開轉址表（2c）
- 點讚、我有、想要、追蹤記的是這些公開識別碼，**刻意不對內容表設外鍵**。理由：SQLite 事後加外鍵必須整張重建，違反「禁止重建表」；內容一律軟刪除（維基式要能還原），不會留下孤兒。孤兒檢查放在備份腳本裡順便跑
- 所有時間存 ISO 8601 UTC 字串

## 四、API

回應一律 JSON。錯誤統一 `{ "error": { "code": "EMAIL_TAKEN", "message": "這個 Email 已經註冊過，直接登入就好" } }`：`code` 給 App 判斷，`message` 直接顯示。寫入都是「設成某狀態」（`on: true/false`），不是切換，App 斷線重送不會反轉。

### 2a 已做

| 方法 | 路徑 | 登入 | 說明 |
|---|---|---|---|
| POST | `/api/auth/register` | — | email、password、handle、name、turnstileToken → 201，寄驗證碼 |
| POST | `/api/auth/verify-email` | — | email、code（、client） → 驗證並登入 |
| POST | `/api/auth/resend-code` | — | email → 重寄驗證碼（不透露帳號狀態） |
| POST | `/api/auth/login` | — | email、password、turnstileToken（、client: "app"） |
| POST | `/api/auth/logout` | 要 | 刪這個 session、清 cookie |
| POST | `/api/auth/forgot-password` | — | email、turnstileToken → 一律回 ok |
| POST | `/api/auth/reset-password` | — | email、code、password → 重設、**其他裝置全部登出**、這台登入 |
| GET | `/api/me` | 選 | `{ user, state }`，沒登入回 `{ user: null, state: null }`；網頁開站只打這一支 |
| GET | `/api/me/state` | 要 | `{ liked, owned, wanted, follows }` |
| POST | `/api/me/likes` | 要 | `{ share, on }` |
| POST | `/api/me/holdings` | 要 | `{ kind: owned／wanted, key, on }` |
| POST | `/api/me/follows` | 要 | `{ artist, on }`；DELETE＝清掉全部追蹤 |
| GET | `/api/users/{handle}` | — | 公開：名稱、簡介、是否認證、我有／想要。追蹤與點讚不公開 |

`client: "app"` 時 token 放在回應 body，不發 cookie；網頁版 token 只在 HttpOnly cookie，JavaScript 拿不到。

### 2b 預定

`GET /api/shares`（分頁、排序、只看在賣、追蹤中）、`GET /api/shares/{n}`、`POST /api/shares`、`PATCH /api/shares/{n}`（出售狀態）、`POST /api/uploads`（取得上傳位置，見第七節）、`GET /api/artists/{slug}`、`GET /api/series/{slug}/{no}`、`POST /api/shares/{n}/offers`、`POST /api/offers/{id}/respond`、`POST /api/offers/{id}/withdraw`、`POST /api/shares/{n}/close`、`GET /api/threads`、`GET/POST /api/threads/{id}/messages`、`POST /api/reports`、`POST /api/appeals`、`GET/POST /api/admin/...`（role=admin）。

### 2c 預定

`GET /api/revisions?target=`、`POST /api/revisions`（編輯）、`POST /api/revisions/{id}/revert`、`POST /api/internal/budget-alert`（預算通知 webhook，驗簽章）。

## 五、登入流程

```
註冊：填 Email／密碼／帳號名／顯示名稱 ＋ Turnstile
  → POST /api/auth/register → 寄 6 位數碼（本機印在 dev server 終端機）
  → 同一個面板切到「驗證 Email」→ POST /api/auth/verify-email → 登入完成
登入：Email／密碼 ＋ Turnstile → POST /api/auth/login
  ├ 密碼對、已驗證 → 發 session
  ├ 密碼對、未驗證 → 403 EMAIL_UNVERIFIED，自動寄碼，面板切到驗證步驟
  └ 錯 → 401「Email 或密碼不對」（帳號不存在也跑一次雜湊，時間上看不出差別）
忘記密碼：Email ＋ Turnstile → 寄重設碼 → 碼＋新密碼 → 其他 session 全刪 → 登入
```

- 未登入按點讚、我有、想要、追蹤 → 彈登入小面板（不跳頁），登入成功後**補做剛剛那一下並一律設成「打開」**（訪客看到的都是沒按，所以不會把帳號裡已經按過的反而取消），留在原頁
- `/login?next=` 是整頁版，給直接打網址、`/me` 沒登入時用
- 選「6 位數碼」而不是信裡的連結：App 裡不用處理深層連結，手機收信切回來打 6 個數字就好
- 密碼雜湊用 WebCrypto 的 PBKDF2-SHA256，**Workers 上限 100,000 次**（超過直接丟錯，本機 dev 不會擋，只在正式環境爆，[workerd #1346](https://github.com/cloudflare/workerd/issues/1346)）。OWASP 建議 SHA-256 要 600,000 次，100,000 次偏低，靠 Turnstile＋登入頻率限制補。次數跟著雜湊存，平台放寬後登入時重新雜湊即可升級
- **CPU 時間風險**：免費方案每次請求 CPU 上限 10ms（[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)），100,000 次 PBKDF2 可能超過。只有註冊、登入、重設這三支會碰到。2c 部署後要實測；超過就降次數（例如 50,000）而不是升級付費，這條寫在「部署前檢查」

### CSRF 與 cookie

- cookie：`yz_session`，HttpOnly、SameSite=Lax、https 時加 Secure、30 天
- cookie 驗證的非 GET 請求一律檢查 `Origin` 必須同站，否則 403 `BAD_ORIGIN`；Bearer 不用（瀏覽器不會自動帶）

## 六、權限

| 角色 | 能做 |
|---|---|
| 訪客 | 看所有公開內容、個人頁的我有／想要 |

「認證帳號」目前等於「能登入的帳號」。之後若開放社群登入（Google、LINE），另外加 `verified_level` 欄位區分，不改現有欄位意義。

## 七、R2 容量上限與讀取計數（2b 做上傳、2c 做防線）

R2 免費額度：儲存 10 GB-月、Class A（寫入、列出）每月 100 萬次、Class B（讀取）每月 1,000 萬次、流量免費（[R2 價格](https://developers.cloudflare.com/r2/pricing/)）。

- **容量**：`photos.bytes` 加總＝已用量，每次上傳前在 D1 查一次（不列 R2 物件，列出算 Class A）。總量上限 8 GB（留 2 GB 緩衝），到了就停新上傳、表單顯示一行說明。每人上傳上限（例如每則 6 張、每人 300 MB）同一個查詢算
- **上傳前壓縮**：瀏覽器端縮到長邊 1600px、WebP／JPEG 品質 0.8（現在表單已有 `lib/image.ts` 的 shrink）；伺服器端再擋單檔 > 2 MB
- **讀取**：照片經 Worker 路由 `/img/{key}` 出，加 `Cache-Control: public, max-age=31536000, immutable`，讓 Cloudflare 快取接住大部分讀取，快取命中不算 R2 Class B
- **計數**：Worker 每次真的去 R2 拿（快取沒中）就在 `usage_daily` 加一；月累計超過 800 萬次（Class B 的 80%）改回佔位圖。這個計數本身寫 D1，要注意 D1 每天 10 萬次寫入額度：用「每 50 次寫一次」的批次計數，或只在快取沒中時才寫
- **暫停模式**：`settings.paused = 1` 時停上傳、停照片讀取（回佔位圖），第三道防線（預算通知 webhook）就是把它設成 1

## 八、零花費三層防線（2c）

1. R2 總容量 8 GB 上限停上傳（第七節）
2. 照片快取＋每月讀取計數，接近免費額度改佔位圖（第七節）
3. Cloudflare 預算通知（已建：≥ US$1）改打 webhook 到 `/api/internal/budget-alert`，驗簽章後把 `settings.paused` 設 1

Workers、D1 維持免費方案，超過額度是請求失敗（D1 回錯誤，[D1 價格](https://developers.cloudflare.com/d1/platform/pricing/)），不會扣款。

## 九、遷移策略

- schema 真相源：`網站/db/schema.ts`；改完 `npm run db:generate` 產生 `drizzle/00xx_*.sql`，**產生的 SQL 要人工看過再 commit**
- **只准**：CREATE TABLE、ALTER TABLE ADD COLUMN（要有預設值或可為 NULL）、CREATE INDEX、INSERT 系統設定值
- **禁止**：DROP TABLE、DROP COLUMN、RENAME、改欄位型別或約束。drizzle-kit 碰到這類變更會產生「建新表→搬資料→刪舊表」的 SQL，看到 `__new_` 開頭的暫存表就是它，**一律退回改設計**。欄位不用了就留著、程式不讀；要改語意就加新欄位
- 本機：`npm run db:migrate:local`（`wrangler d1 migrations apply DB --local`，設定檔 `wrangler.local.jsonc`），已套用的記在 `d1_migrations` 表，重跑無變更
- 正式（2c）：部署前先做一次站外備份，再 `wrangler d1 migrations apply --remote`；遷移只在部署流程裡跑，不從任何 API 觸發

## 十、備份策略（2c 實作，設計先定）

- D1 內建 Time Travel：免費方案可還原到 7 天內任一時間點（付費 30 天）（[D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)）。這是第一層，但它在 Cloudflare 裡面，不算站外
- **站外備份**：每週一次（加每次遷移前），在使用者電腦跑 `wrangler d1 export --remote --output`（SQL 檔）→ 壓縮 → 存到 OneDrive `_個人資料/音藏/備份/D1/`，保留最近 12 份週備份＋每月第一份永久保留
- **R2 照片**：同一支腳本比對 `photos` 表與本機備份資料夾，只下載新增的照片（下載算 Class B，量很小）
- 備份腳本順便跑孤兒檢查（likes／holdings／follows 指到不存在的內容）與筆數守恆（這次匯出的每張表筆數 ≥ 上次，除非有軟刪除）
- 每季做一次還原演練：把最新備份匯入本機 D1，跑首頁與個人頁

**台灣收信可達性**：Gmail、Yahoo 奇摩、Hinet、各校信箱的到達率，三家都**查不到公開數據，待實測**。實測方法：接上之後用同一封驗證信寄到 Gmail、Yahoo 奇摩、Outlook、Hinet 各一個信箱，看進收件匣還是垃圾信。不管哪一家，寄件網域有沒有設好 SPF、DKIM、DMARC 影響最大。

**建議先註冊 Resend**：額度夠朋友測試期用（每天 100 封，一次註冊寄 1 封）、API 最簡單、超額是停寄不扣款、跟零花費原則一致。**卡點是寄件網域**：音藏還沒買網域，要用使用者既有網域的子網域（例如 `mail.dblzm.com` 或 stmusictraveler.com 底下）加 SPF／DKIM 紀錄；只加 DNS 紀錄，不用把整個網域搬到 Cloudflare。寄件人會顯示那個網域，這點要使用者決定。

## 十八、2c 實作：維基式編輯、下架、藝人頁顯示、熱門藝人

遷移 `drizzle/0002_2c.sql`：新表 `revisions`、`page_locks`、`deals`、`artist_dismissals`；`artists／series／items／versions／shares` 各加一個可為 NULL 的 `hidden_at`；`artists` 加 `display`（常數預設 `auto`）；`photos` 加兩個索引。沒有 `__new_`、DROP、RENAME。

**維基式編輯**（`lib/server/wiki.ts`）
- 對象：`artist:{slug}` 的 intro、`series:{slug}/{no}` 的 body。`artists.intro`／`series.body` 仍是「目前版本」，每次修改另存一筆 `revisions`（整份內容，JSON 段落陣列）

- 同時編輯：送出時帶 `baseId`（開始編輯時的最新版本 id），不一致回 409 `EDIT_CONFLICT`，不會默默蓋掉別人的修改
- 第一次有人編輯時，先把原本的內容存成「初始版本」（作者＝建立者，時間＝建立時間），歷史才完整；還沒人編輯過的頁面，歷史頁顯示一筆虛擬的初始版本
- 還原＝新增一筆內容等於舊版的紀錄（`reverted_from` 指向舊版），說明自動寫「還原到第 N 版」，不刪任何紀錄
- 差異：`lib/diff.ts` 先比段落（LCS），相鄰的刪一段＋加一段視為改寫再逐字比；兩邊字數相乘超過 400 萬就整段換，避免耗 CPU
- 維基百科來源：藝人有 `wiki_url` 時，每一筆 revision 都記 `license = CC BY-SA 4.0`；頁面保留「來源：維基百科＋條目連結＋CC BY-SA 4.0」，有人改寫後加一句「音藏使用者改寫的版本同樣以此授權」，歷史頁也有授權說明
- API：`GET /api/revisions?target=`、`POST /api/revisions`、`POST /api/revisions/{id}/revert`、`POST /api/admin/page-lock`

**管理員下架**（`lib/server/takedown.ts`）
- 隱藏：藝人、系列、品項、版本、炫收藏設 `hidden_at`。內容讀取（`content.ts`）與存在性檢查（`me.ts`、`trade.ts` 的 `shareRow`）都排除，所以頁面 404、牆上不出現、API 當不存在（點讚、出價回 404）。恢復＝清掉 `hidden_at`
- 永久刪除只限空頁面：底下有任何炫收藏（含已隱藏、已刪除）、任何人的我有／想要、任何檢舉紀錄、任何炫收藏提到這位藝人、或別的系列把他列為共同署名／客串／合輯，一律 409 `HAS_CONTENT` 並列出擋下原因。炫收藏本身只能隱藏
- 刪除前把整列內容存進 `admin_log.detail`（快照），必要時可手動補回；系列號記進 `counters` 的 `series_no:{slug}`，新增系列取「現有最大號與記錄的最大號」再加一，永不重用；版本號改用「最大號＋1」
- API：`POST /api/admin/hide`、`/purge`、`/display`；後台 `/admin` 的「下架」區塊

**藝人頁顯示**（`lib/catalog.ts` 的 `artistVisible`）：`display = auto` 時，有主要系列、客串、合輯收錄或任何相關炫收藏才顯示，否則藝人頁 404、不出現在目錄、熱門藝人、搜尋；`on` 強制顯示、`off` 強制不顯示。炫收藏表單仍列出所有已核准藝人（名單先匯入，有人發了收藏才自動出現）。

## 十九、歷史價格的計算方法

程式：`lib/prices.ts`（純函式）、`lib/server/prices.ts`（讀 D1）。

| 步驟 | 規則 |
|---|---|
| 記錄 | 賣家「成交」時寫一筆 `deals`：版本鍵、成交價、日期、賣家、買家、那筆出價。沒選版本的收藏 `version_key` 為 NULL，不進行情 |
| 作廢 | 賣家把已售出改回出售中 → 那筆標 `voided_at`（不刪），不再計算 |
| 只算認證帳號 | 計算當下，買賣雙方都必須是已驗證 Email；那則收藏沒被刪除或隱藏 |
| 近期 | 最近 365 天，最多取最新 20 筆 |
| 同一對只算一次 | 同一版本、同一個「賣家→買家」只留最新那筆 |
| 排除離群值 | ①價格不在中位數的 1/3～3 倍之間的排除（小樣本也能用）；②排除後仍有 5 筆以上，再用中位數絕對偏差（MAD）算修正 z 分數，絕對值 > 3.5 的排除（Iglewicz–Hoaglin 建議門檻） |
| 顯示門檻 | 排除後不足 3 筆 → 整塊不顯示（連開價、出價區間也不顯示） |
| 顯示內容 | 近期成交區間（最低～最高）、中間值、走勢（SVG 折線，舊到新）、筆數與日期範圍；目前開價區間＝這個版本定價出售中的收藏；目前出價區間＝這個版本出售中收藏的「等回覆／已接受」出價。被檢舉鎖定的收藏不算開價與出價 |
| 隱私 | 前台與 API 都不回傳買賣雙方是誰 |

## 二十、零花費第二、三道防線的實作

**第二道：照片每月讀取計數**（`lib/server/guard.ts`、`app/img/[...key]/route.ts`）
- 讀照片先查 Cloudflare 快取（Cache API，`caches.default`）；沒中才讀 R2，並把快取補上。只有真的讀 R2 才計數（R2 Class B 只在這時候發生）
- 計數存 D1 `counters` 的 `r2_reads:YYYY-MM`（UTC 月份，跟 R2 帳單同一個月）。沒有另開 `usage_daily` 表（原規劃），直接用既有的 `counters`
- 為了省 D1 寫入額度，同一個 Worker 執行個體累積 20 次才寫一次（`FLUSH_EVERY`）。執行個體被回收時還沒寫的會少算，誤差最多「執行個體數 × 20」，所以門檻留 20% 緩衝
- 門檻：預設 800 萬次＝R2 Class B 免費額度每月 1,000 萬次的 80%（[R2 價格](https://developers.cloudflare.com/r2/pricing/)）。管理員可用 `POST /api/admin/pause { readLimit }` 調整（存 `settings.photo_read_limit`）
- 達門檻 → `/img/` 回佔位圖（SVG，`Cache-Control: no-store`，表頭 `X-Photo-Placeholder: limit`），不讀 R2；文字照常。下個月計數鍵換新，自動恢復
- 所有 `/img/` 回應都加 `X-Content-Type-Options: nosniff`

**第三道：預算通知 webhook → 暫停模式**
- 端點 `POST /api/internal/budget-alert`，驗共用密鑰：表頭 `cf-webhook-auth` 必須等於環境變數 `BUDGET_WEBHOOK_SECRET`（常數時間比對）；沒設密鑰整支回 503；錯的回 401；同一 IP 每小時 30 次
- 驗過 → `settings.paused = 1`，寫操作紀錄（作者「系統」）。暫停模式：停上傳（`acceptUpload` 回 503）、停讀照片（佔位圖 `X-Photo-Placeholder: paused`）、文字照常。管理員在 `/admin`「網站狀態」按「解除暫停」
- **限制（需使用者知道）**：Cloudflare 通知的 webhook 目的地「帳號裡至少要有一個 Pro 以上方案的網域才能用」（[Configure webhooks](https://developers.cloudflare.com/notifications/get-started/configure-webhooks/)）。音藏是免費方案，預算通知目前只能寄信。部署手冊寫了兩個替代方案（Google Apps Script 讀預算通知信後打 webhook，或只靠寄信＋手動暫停）

**申訴證據照片**：新上傳的申訴照片放 `a/` 開頭，`/img/a/...` 只給上傳的本人與管理員（其他人 404，`Cache-Control: private, no-store`、不進快取）；舊資料若 `purpose = appeal` 但放在 `p/`，一樣檢查身分。

## 二十一、不給搜尋引擎收錄、分享預覽

- 開關：環境變數 `ALLOW_INDEXING`，預設 `0`（不收錄），設 `1` 一次打開
- 關閉收錄時兩種方式同時有：每頁 `<meta name="robots" content="noindex">`（`app/layout.tsx` 的 `generateMetadata`）、每個回應 `X-Robots-Tag: noindex`（`proxy.ts`）
- `robots.txt` **不全站 Disallow**（2026-09-27 主對話修正）：擋了爬蟲就讀不到頁面上的 noindex，反而可能只憑網址收錄；FB、Threads 的預覽爬蟲也遵守 robots.txt，擋了分享出去沒有預覽圖。現在是 `Allow: /`，只擋 `/admin`、`/api/`
- 單則炫收藏頁有 Open Graph：`og:title`（那則的標題）、`og:description`（想說的話，沒有就「某某的 CD」）、`og:image`（那則的主圖，絕對網址）、`og:url`，另加 `canonical`

## 二十二、備份與還原（2c 實作）

- 腳本：`網站/scripts/backup.mjs`（包裝 `backup.sh`、`backup.bat`）。`--remote` 正式、`--local` 本機試跑
- 產出：`備份/{YYYYMMDD-HHmm}-remote/d1.sql`＋`manifest.json`（每張表筆數、這次新下載的照片、孤兒檢查、跟上一份比筆數變少的表）；照片累積同步到 `備份/R2-remote/`，只下載本機沒有的（檔名是隨機 id、內容不會改，不按日期重複存）
- 還原：`網站/scripts/restore.mjs <d1.sql>`。`wrangler d1 export` 的順序是一張表的 CREATE＋INSERT 再下一張，子表排在 `users` 前面，直接執行會撞 `no such table: main.users`；這支先重排成「全部 CREATE TABLE → 全部 INSERT → 索引」再執行，只准還原到新的空資料庫
- D1 Time Travel（Cloudflare 內建，不算站外）：免費方案可還原到 7 天內、付費 30 天。指令 `wrangler d1 time-travel info <資料庫>`、`wrangler d1 time-travel restore <資料庫> --timestamp=<UNIX 時間>` 或 `--bookmark=<書籤>`；還原會**原地覆蓋**整個資料庫、中斷進行中的查詢，還原後會回報前一個書籤可以反悔（[D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)）
- 排程：每週一次＋每次部署前（`deploy.sh` 已內建遷移前備份）。使用者電腦要開著、已登入 wrangler；排程方式等部署時跟使用者確認（Windows 工作排程器或手動）
