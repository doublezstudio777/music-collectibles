## 誠實揭露：這次驗收照不到的地方

1. **正式站目前沒有任何公開收藏（真實照片）**：`/share/1`～`/share/5` 全部 404，首頁「追蹤中」「最新」分頁都是空清單。這代表「照片分級」「浮水印顯示」「辨識細節公開頁不含條碼」這三項在**正式站**只能驗證到「頁面結構與 API 行為符合設計」，沒有一張真實照片可以在正式站上實測 401/200/浮水印肉眼效果——這幾項的真人資料驗證只在本機（新建的測試收藏）做過。等第一位朋友真的發了炫收藏，建議回頭在正式站上抽驗一次這三項。
2. **限流的「刻意分散多資料中心」情境測不到**：本機與正式站都只能驗證「單一來源狂抓會被擋」，PM 報告與我都沒有辦法（也不該在正式站）模擬真正分散式爬蟲。這是 PM 已知問題 #1 誠實列出的，我沒有能力補這個洞，維持「已知限制」處理。
3. **分享圖（下載圖）的浮水印像素級比對**沒有重做，沿用 PM 報告的截圖判斷（`img/分享圖_貼文.jpg`）為合理，沒有再用 `getComputedStyle`／取色逐點驗證——如果要更硬的證據，下次有真實收藏時可以照做。
4. **私訊頁是否也有獨立一套（未同步地區限制的）出價/接受按鈕**：這是我在筆記裡記過的音藏 1.5 階段舊缺陷型態（不同頁面各自重寫交易判斷）。這次讀碼確認 `components/inbox.tsx` 的出價／我要買／接受／拒絕／撤回全部呼叫同一組 `/api/offers/{id}/respond`、`/api/shares/{n}/offers`，跟單則頁共用同一套後端擋，**沒有找到同型缺陷復發**，但我沒有走 Playwright 實機在私訊頁點過海外帳號的按鈕（本機建帳號較費工，改用 API 直打驗證行為，屬本筆記手藝三十七條「越權測試全走 API」的判斷）。
