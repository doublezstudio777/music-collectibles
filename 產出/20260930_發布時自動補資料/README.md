# 發布時自動補資料（三層方案第 1 層）

狀態：**本機驗收完成、待部署**。分支 `feat/autofill`，沒合回 main、沒上正式站：`feat/my-page` 還沒合回 main，照派工規則不搶部署。

## 做法

- 會員（或管理員）在炫收藏表單新增藝人、系列、版本時，`recordAddition` 在 `autofill_jobs` 排一筆工作，用 `waitUntil` 在背景跑，表單照常立即回應
- 背景沒跑完的（額度用完、MusicBrainz 503），由新的排程 `*/10 * * * *` 接手；後台打開「待確認的新增」也會順手跑到期的工作
- D1 鎖確保同時只有一個執行在跑；MusicBrainz 每次間隔 ≥1.1 秒，上次呼叫時間存 D1。User-Agent `Lemibox/0.1 ( https://lemibox.com )`。503 先等 3 秒重試一次，還忙就整批排到 2 分鐘後
- Wikidata：藝人高信心時，用 MusicBrainz 連到的 QID 跑 SPARQL 取 P31／P21／P27／P495／P740，再用 wbgetentities 取繁中、英、韓、日標籤當別名；MusicBrainz 查無時用 wbsearchentities 列同名候選
- 只取事實欄位，藝人簡介、系列介紹不碰，不抓任何維基百科文字。不呼叫 AI，零費用

### 信心分級

| 等級 | 條件 | 動作 |
|---|---|---|
| 高 | 條碼吻合；或名稱＋年份＋作品吻合且只有一個候選（藝人：作品標題與年份；系列：藝人、標題、年份或曲目；版本：系列、格式、年份，有地區就加地區） | 只補空白欄位，改前的值存 `applied`，駁回時還原（只還原「還是自動填的值」的欄位） |
| 低 | 同名但佐證不夠、多個候選、沒填年份、只有數位版 | 只列候選連結，不預填；每個候選旁有「用這筆」 |
| 未查到 | MusicBrainz、Wikidata 都沒有同名 | 標示 |
| 重複 | 跟站上既有藝人或系列同 MBID、同藝人同標題同年份、版本對到的發行已經掛在同品項另一個版本 | 不預填，核准＝改掛到既有那筆 |

- 先後關係：藝人剛建時還沒有作品可比；之後同一位藝人底下新增系列、系列底下新增版本時，上一層還沒定案的工作會重排。版本會等系列查完再查，最多等 40 分鐘
- 系列高信心會把 MusicBrainz 的實體正式發行建成版本（source＝musicbrainz、資料狀態待確認、不計分）。同品項如果有會員建的版本還沒對上，那一品項先不建，等版本比對完再建
- 會員稍後新增的版本如果跟自動建的是同一版，會併進會員那筆，自動建的那筆收掉
- 自己的結果不拿來當佐證：條碼、曲目只算人填的，自動補資料帶進來的不算

### 後台（`/admin/additions`）

每筆新增下面顯示信心等級、預填了什麼、來源連結、候選。按鈕：核准（重複的顯示「核准（改掛過去）」，會直接改掛）、駁回預填、重查（可填 MBID 或條碼）、改掛到既有的（重複時已帶好目標）、修改名稱。

### 表單

「新增版本」多一欄「條碼數字（選填）」，給條碼優先比對用。

## 管理員新增的內容（提案，已先照這個做）

照樣自動查，高信心一樣預填，後台看得到結果、也能駁回；但管理員自己新增的本來就算確認過，不進「待確認」。不要查的話，改 `additions.ts` 的 `recordAddition` 一行就好。

## 驗收

- `_後台驗收_本機.py`：16 項過 15 項。後台 1440／390 各 12 個區塊、四種信心都顯示、沒有橫向溢出、console 0 錯。核准重複系列、版本＝改掛並軟刪除；駁回預填：系列 MBID 與類型還原、自動建的 2 個版本收掉、會員版本還在；重查後重新預填
- 沒過的 1 項：操作過程出現 2 筆 404，是新增列名稱連結（`/artist/a-q25y`、已改掛的 `/artist/hyukoh/2`）的 RSC 預先載入。那些 Link 原本就在，不是這次加的；這次加的重複目標連結改用一般 `<a>`
- tsc 0 錯、lint 0 錯（1 個 layout 字型警告是原本就有的）
- 舊驗收 `20260929_用字與版本欄`：拿正式站備份跑，15 過 3 敗，第 4 段中斷。都是資料不同：那支腳本寫給本機示範資料，正式站的 `sunset-rollercoaster/1` 標題是「My jinji 日版」、CD 底下沒有「一般版」。沒做改前改後對照
- 第一次跑遇到 MusicBrainz 503 兩次，工作 2 分鐘後自動重跑成功；之後加了「等 3 秒重試一次」
