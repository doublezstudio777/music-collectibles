- 兩頁頁首都有黑框「**草稿，待律師確認**　最後更新 2026-09-28」；頁尾全站加「隱私權政策」「使用條款」兩個小連結

- **隱私權政策**：一張表寫蒐集什麼、什麼時候蒐集、用途、保存期限，涵蓋防盜版 README 的 8 項（連線國家、註冊與最近登入國家、每日活動紀錄 90 天、所在地區公開到國家、瀏覽次數、IP 暫時使用、管理員看得到的範圍、照片浮水印）；另有哪些資訊公開、交給誰處理（Cloudflare、Resend、Google Fonts）、Cookie、不販售、當事人權利與申請方式、政策更新。手機版的表改成一筆一段，不用橫捲

- 驗收掃過兩頁內文：沒有中國用語、路標句、破折號

## 二、刪除帳號改申請制

- 設定頁拿掉自助刪除表單，最底下只剩一個灰色小連結「申請刪除帳號」→ `/settings/delete`：列出刪除後會怎樣，填原因（必填，500 字內）送出。送出後帳號照常可用，可以取消
- 後台新分頁「刪帳申請」`/admin/deletions`，儀表板待處理多一格「刪帳申請」件數。每筆顯示暱稱、帳號、Email、申請時間、註冊日、炫收藏數、照片張數與容量、原因
- 管理員按「執行」→ 可勾「連同照片一起刪除（本人明確要求時才勾）」→ **二次確認：要打出這位會員的帳號名**，「確定刪除」才能按（API 也檢查）。同一筆不能再執行
- 執行內容（`lib/server/deletion.ts`，D1 寫入全在同一個 batch，失敗整批不生效；R2 刪檔在交易成功後）：

| 處理 | 內容 |
|---|---|
| 刪除 | Email、密碼、sessions、驗證碼、`user_geo`、`user_activity`（所在地區的來源）、跟這個帳號有關的限流與每日計數、改名紀錄、大頭貼 |
| 改成匿名 | 暱稱「已刪除的會員」、帳號名 `del-` 加 10 碼亂數、簡介清空、`status=deleted`。Email 欄位不能空也不能重複，改成 `{代號}@deleted.invalid` |
| 保留 | 炫收藏、編輯紀錄、留言、出價、私訊、成交紀錄、讚、我有／想要、分數 |
| 照片 | 預設保留；有勾才把他上傳的照片標刪除、R2 刪檔、容量扣回、清快取 |
| 操作紀錄 | 寫一筆「執行刪除帳號」（各表清掉幾列，不含 Email）；舊的後台紀錄 target `user:{舊帳號名}` 改成新代號 |

- 刪帳後：單則頁、留言、系列頁貢獻者都顯示「已刪除的會員」；個人頁 `/u/del-…` 只剩暱稱與炫收藏（沒有所在地區、等級、我有想要）；舊帳號名網址 404；舊 token 失效、舊 Email 登不進去；「已刪除的會員」不佔用暱稱，別人可以用他刪帳前的暱稱
- 遷移只新增：`deletion_requests`、`user_name_changes` 兩張表，`users` 加 4 個可為 NULL 的欄位（`name_key`、`name_changed_at`、`avatar_key`、`deleted_at`）與一個索引。沒有 `__new_`、DROP、RENAME

**刪帳前後筆數對照**（驗收 2i～2zd，D1 不勾照片、D2 勾照片；兩位各先建好下列資料）：

## 三、改暱稱

- 設定頁「暱稱」一格，說明「每 30 天可以改一次，不能跟別人重複」；改過之後輸入框鎖住，顯示「2026-10-27 以後可以再改」。API 在 30 天內回 429
- **全站唯一**：比對鍵＝NFKC（全形轉半形）→ 小寫 → 拿掉所有空白與零寬字元，存在 `users.name_key`。註冊與改名都檢查；已刪除的帳號不參加比對
- **保留字**（`lib/server/names.ts`）：名字裡含「已刪除的會員」「館長」「音藏」（站名）「管理員」「站長」就不行；整個名字等於「官方、客服、系統、管理者、admin、system、yinzang」等也不行。管理員帳號不受保留字限制
- 不設唯一索引：正式站舊帳號萬一已重複，唯一索引會讓遷移失敗。舊帳號沒有 `name_key`，每次比對前先補（補完後只是一次空的索引查詢）
- 改名紀錄寫進 `user_name_changes`，只在後台會員頁顯示（暱稱底下「改名 N 次」，點開看每次的舊名→新名與時間）；一般會員打這支 API 403，公開個人頁看不到
- **整頁快取**：`users` 本來就有內容版本觸發器。實測改名前單則頁 HIT → 改名後版本號 +1 → 下一次 MISS 且是新名字、沒有舊名字 → 再下一次 HIT（驗收 3o～3r）。什麼都沒改的送出不寫 `users`，不會白白讓快取作廢

**正式站重複暱稱**：部署後用 `_正式站暱稱檢查.py`（唯讀）查過，正式站目前只有 1 位會員，沒有重複、沒有含保留字的暱稱。

## 四、大頭貼

- 設定頁「大頭貼」：選一張照片，瀏覽器從中間裁成正方形、縮成 256×256 WebP（`lib/image.ts` 的 `prepareAvatar`；舊 Safari 不支援 WebP 編碼時退回 JPEG），伺服器只看檔頭格式、寬高是不是 256×256、大小 100KB 以內，不做影像處理。可以移除，回到暱稱字樣頭像
- 存 R2 `v/{id}.webp`，`photos` 表記一列（purpose=avatar），計入 `counters.r2_bytes`（8GB 上限）。每天最多換 5 次（第 6 次 429；移除不算）
- 換掉或被移除的舊檔：photos 標刪除、R2 刪檔、容量扣回、清這個資料中心的快取；`/img/` 先查 D1，其他資料中心的快取副本也不會再送出（驗收 4h～4j、4u～4v）
- 顯示位置：頭像選單、個人頁、留言、出價列表、系列頁貢獻者名單（新元件 `components/ava.tsx`）。沒有大頭貼沿用原本的暱稱字樣頭像；留言與貢獻者原本沒有頭像，這批一起加上字樣頭像
- **檢舉**：個人頁大頭貼下方「檢舉大頭貼」（別人才看得到），走既有檢舉表，target＝`avatar:{照片 id}`，理由「不當圖片或冒用他人」／其他；只有認證帳號、一人一次、不能檢舉自己。大頭貼不鎖交易
- **管理員處理**：審核頁新增「被檢舉的大頭貼」一區（移除大頭貼／保留），儀表板多一格「被檢舉的大頭貼」；後台會員頁每位有大頭貼的會員旁也有「移除大頭貼」。移除寫操作紀錄。換掉或移除後，舊照片的檢舉不再列出

## 已知問題與取捨

1. **法務頁日期**：頁面寫「最後更新 2026-09-28」，跟專案檔名一致；但施工時系統時鐘是台灣時間 2026-09-27 晚上。要改日期只改 `components/legal.tsx` 的 `LEGAL_UPDATED`
2. **隱私權政策的聯絡信箱是「待補」**：目前網站沒有收信信箱（Resend 的 `notify.dblzm.com` 只寄不收）。要你決定用哪個信箱
3. 兩支舊腳本第一次沒全過，都是驗收資料被別的腳本弄髒，不是程式問題：`其他系列與評論區` 2h 每跑一次就在夜貓組多一個系列（README 已記載，把殘留的驗收系列隱藏後 95/95）；`上線後第一批` 挑「最新一則有照片的收藏」，挑到的是別支腳本借用同一張照片檔名建的 1,153 則收藏之一，`/img/` 依檔名查到的是另一則沒被隱藏的收藏。另建一則有獨立照片的收藏後 65/65
4. 本機驗收有一次 console 出現首頁 RSC 預先載入 500（Miniflare 報 Worker hung），發生在改名後立刻點連結換頁、預先載入被瀏覽器中斷時；之後重跑兩次沒再出現，`worker.ts` 整頁快取的邏輯這批沒動（只加了兩個路徑）。正式站 100 次瀏覽沒有 503
5. 刪帳後，這個人還在賣的收藏與還在等回覆的出價不會自動收掉（規格只說保留貢獻內容）。買家還是看得到「開放出價」，但對方不會再回。要不要刪帳時一併改回純分享、撤回出價，要你決定
6. 刪帳時大頭貼一律刪除（屬於個人識別，跟暱稱同性質），簡介也清空；規格沒明寫這兩項，我照「暱稱改成已刪除的會員」的同一個原則處理
7. 瀏覽次數計數（`counters` 的 `quota:*`）沒有保存期限，政策寫「待定」。要設 90 天的話，清理排程加一行即可
8. 暱稱唯一靠程式檢查，兩個人在同一瞬間註冊同一個暱稱理論上可能都成功（沒有唯一索引）；會員量這麼小，實際碰到的機率很低
9. 大頭貼網址 `Cache-Control: public, immutable`：被移除後，看過的人瀏覽器裡可能還留著舊檔，但網站頁面已經不再引用它，其他人拿網址去打是 404
