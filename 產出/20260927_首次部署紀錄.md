### PBKDF2 在正式環境的 CPU

5 萬次讓登入的 CPU 落在 19～35ms，高於免費方案標示的 10ms，但 Cloudflare 沒有擋（全部 ok）。同一批資料裡，不做雜湊的頁面也常超過 10ms：`/login` 頁面 9～44ms、驗證信箱 27ms，p90 14ms。也就是說 10ms 上限目前不是逐次硬擋，超過的不只登入。免費方案這條限制怎麼計算，Cloudflare 沒寫得很細，**上線後持續看 tail 或 Metrics 有沒有出現 exceededCpu**；真的出現時，先考慮降到 2 萬次（本機實測約 2.9ms）。

## Windows 每週備份排程（沒有建，給使用者自己貼）

新增 `網站/scripts/backup-weekly.sh`：從 `_私人/cloudflare.txt` 讀 Cloudflare 金鑰（不印出）、補上 nvm 的 node 路徑、跑正式備份、結果附加到 `備份\backup.log`。已從 Windows 的 cmd 經 `wsl.exe` 實測成功。

在 Windows 的「命令提示字元」貼上（每週日 21:00，電腦要開著）：

```
schtasks /Create /TN "音藏每週備份" /SC WEEKLY /D SUN /ST 21:00 /TR "wsl.exe -d Ubuntu -- bash -lc \"exec ~/AboutAI/*/music-collectibles/*/scripts/backup-weekly.sh\"" /F
```

- 路徑用 `*` 代替「專案」「網站」兩段中文，是因為從 cmd 傳中文路徑給 wsl.exe 會變亂碼（實測踩到）
- 排程只在登入狀態下執行（預設）；想登出也跑，要加 `/RU 使用者名稱 /RP` 並輸入 Windows 密碼
- 立刻試跑：`schtasks /Run /TN "音藏每週備份"`；看結果：打開 `備份\backup.log` 看最後一行是不是「== 完成」
- 刪除排程：`schtasks /Delete /TN "音藏每週備份" /F`
