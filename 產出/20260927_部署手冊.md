# 音藏部署手冊（Cloudflare Workers＋D1＋R2）

2026-09-27，Claude Code on Windows。**這份只是準備，還沒部署**；部署要先經使用者同意。
正式網址：`https://yinzang.dblzm.workers.dev`（Worker 名稱 `yinzang`，workers.dev 子網域 `dblzm` 已註冊）。
程式與腳本都在 `網站/`；技術細節見 `產出/20260927_第2階段技術設計.md` 第十八～二十二節。

## 一、部署前使用者要做或決定的事

| # | 事項 | 為什麼 |
|---|---|---|
| 1 | 同意開始部署 | 部署後雲端會出現 Worker、D1、R2 各 1 個（目前都是 0） |
| 2 | 決定密碼雜湊次數 | 本機（i5-12400、Node）實測 PBKDF2 10 萬次約 12.3ms，已超過免費方案每次請求 CPU 10ms 的上限；5 萬次約 6.1ms、2 萬次約 2.9ms。建議先用 10 萬次部署實測，超過就改 5 萬次（第五節有步驟）；也可以一開始就用 5 萬次 |
| 3 | 預算通知要不要接 webhook | Cloudflare 通知的 webhook 目的地要帳號裡有 Pro 以上方案的網域才能用，音藏是免費方案。選項見第六節 |
| 4 | 在 Cloudflare 後台建 Turnstile 小工具 | 網域填 `yinzang.dblzm.workers.dev`，拿到站金鑰與密鑰（見第二節第 4 步） |
| 5 | 備份排程方式 | 每週一次跑 `scripts/backup.bat --remote`，要電腦開著；用 Windows 工作排程器，或手動 |

## 二、建立雲端資源（第一次）

在 `網站/` 底下操作。wrangler 指令一律用專案內的版本：`npx wrangler …`。

1. **登入**：`npx wrangler login`（或設環境變數 `CLOUDFLARE_API_TOKEN`，權限要 Workers、D1、R2 編輯）。`npx wrangler whoami` 看帳號 ID
2. **建 D1**：`npx wrangler d1 create yinzang`，把回報的 `database_id` 填進 `wrangler.production.jsonc`
3. **建 R2 bucket**：`npx wrangler r2 bucket create yinzang-photos`（R2 已開通）
4. **Turnstile**：Cloudflare 後台 → Turnstile → 新增小工具，網域 `yinzang.dblzm.workers.dev`，模式「受管理」。站金鑰填進 `wrangler.production.jsonc` 的 `vars.TURNSTILE_SITE_KEY`
5. **填 `wrangler.production.jsonc`**：`account_id`、`database_id`、`TURNSTILE_SITE_KEY` 三處 `__填入_…__`。部署腳本看到還有沒填的會直接停
6. **設 secrets**（見第三節）

## 三、環境變數與 secrets

| 名稱 | 種類 | 值 | 設定方式 |
|---|---|---|---|
| `TURNSTILE_SECRET` | secret | Turnstile 密鑰 | `npx wrangler secret put TURNSTILE_SECRET --config wrangler.production.jsonc` |
| `RESEND_API_KEY` | secret | `_私人/resend.txt` 的金鑰 | 同上，名稱換 `RESEND_API_KEY`。有設就寄真信，沒設印在 log（正式環境一定要設） |
| `BUDGET_WEBHOOK_SECRET` | secret | 自己產生的隨機字串（`openssl rand -hex 32`） | 同上。沒設時 webhook 整支關閉（503） |
| `TURNSTILE_SITE_KEY` | var | Turnstile 站金鑰 | `wrangler.production.jsonc` 的 `vars` |
| `ADMIN_EMAILS` | var | `zukawork0312@gmail.com` | 同上（已填）。這個 Email 要先在正式站註冊並驗證，才會是管理員 |
| `ALLOW_INDEXING` | var | `0` | 同上（已填）。名稱定案、要給 Google 收錄時改 `1` 再部署 |
| `PBKDF2_ITERATIONS` | var | `100000` | 同上（已填）。CPU 超過時改 `50000`，舊密碼下次登入自動改用新次數 |
| `MAIL_FROM`、`MAIL_REPLY_TO` | var（選用） | 不設就用 `音藏 <noreply@notify.dblzm.com>`、`zukawork0312@gmail.com` | — |
| `MAIL_ALLOWLIST` | var | **正式環境不要設** | 只給本機真實寄信測試用 |

第一次設 secret 時 Worker 還不存在，wrangler 會問要不要先建一個空的 Worker 放 secret，回答要。

## 四、部署

```bash
cd 網站
scripts/deploy.sh --first   # 第一次（雲端 D1 是空的，跳過遷移前備份）
scripts/deploy.sh           # 之後每次
```
Windows 用 `scripts\deploy.bat`（交給 Git Bash／WSL 的 bash 跑同一支，閘門行為一致）。

腳本是一條閘門，**任何一步失敗就停，後面不會跑**：
0. 設定檢查：`wrangler.production.jsonc` 沒有 `__填入_`、已登入、三個 secret 都在
1. 型別、lint、遷移檔掃描（有 `__new_`、DROP、RENAME 就停）
2. 用正式設定建置（`YINZANG_DEPLOY=production npm run build`）
3. 遷移前站外備份（`backup.mjs --remote`；`--first` 跳過）
4. 套用遷移（`wrangler d1 migrations apply DB --remote`），再用 `migrations list` 確認沒有待套用的，否則停
5. 部署程式（`wrangler deploy`）
6. 煙霧測試：首頁 200、`X-Robots-Tag: noindex`、`<meta name="robots" content="noindex">`、`robots.txt`

本機已驗證：`YINZANG_DEPLOY=production npm run build` 可以建置（5 秒），產出的 `dist/server/wrangler.json` 名稱 `yinzang`、綁定 `DB`、`PHOTOS`、`workers_dev: true`，建置結果不含任何密鑰；腳本語法 `bash -n` 通過。實際對雲端執行尚未做。

## 六、預算通知 webhook（第三道防線的 Cloudflare 端）

**限制**：Cloudflare 通知的 webhook 目的地只有「帳號裡至少一個網域是 Pro 以上方案」才能用（[Configure webhooks](https://developers.cloudflare.com/notifications/get-started/configure-webhooks/)）。音藏是免費方案，已建的預算通知（花費 ≥ US$1，policy「音藏 花費超過 1 美元」）目前只寄信到 zukawork0312@gmail.com。

**選項 A：有 Pro 網域時**（目前沒有）：後台 → Notifications → Destinations → Webhooks → Create，URL 填 `https://yinzang.dblzm.workers.dev/api/internal/budget-alert`，Secret 填 `BUDGET_WEBHOOK_SECRET` 的值，Save and Test（Cloudflare 會把 secret 放在 `cf-webhook-auth` 表頭）；再把預算通知的收件方式加上這個 webhook。

**選項 B（免費，建議）**：Google Apps Script 每 10 分鐘看一次 Gmail，有新的預算通知信就打 webhook。
1. 到 script.google.com 新增專案，貼上：
```javascript
function checkBudgetAlert() {
  // 搜尋條件：第一次收到預算通知信後，照實際寄件人與主旨調整
  const threads = GmailApp.search('is:unread subject:(音藏 花費超過 1 美元) newer_than:2d');
  if (!threads.length) return;
  const secret = PropertiesService.getScriptProperties().getProperty('BUDGET_WEBHOOK_SECRET');
  const res = UrlFetchApp.fetch('https://yinzang.dblzm.workers.dev/api/internal/budget-alert', {
    method: 'post',
    contentType: 'application/json',
    headers: { 'cf-webhook-auth': secret },
    payload: JSON.stringify({ source: 'gmail', subject: threads[0].getFirstMessageSubject() }),
    muteHttpExceptions: true,
  });
  if (res.getResponseCode() === 200) threads.forEach((t) => t.markRead());
}
```
2. 專案設定 → 指令碼屬性，加 `BUDGET_WEBHOOK_SECRET`＝同一把密鑰（不要寫在程式碼裡）
3. 觸發條件：`checkBudgetAlert`、時間驅動、每 10 分鐘
4. 搜尋條件要在第一次收到預算通知信時確認寄件人與主旨（**待確認**，目前還沒收過）

**選項 C**：不接 webhook，只靠預算通知信＋管理員看到信後在後台按「手動暫停」。第一、二道防線（容量 8GB、讀取 800 萬次）照常自動運作。

## 七、備份

- 平常：`scripts\backup.bat --remote`（Windows）或 `scripts/backup.sh --remote`，備份到 `D:\OneDrive\Claude-Data\_個人資料\音藏\備份\`：每次一個 `{日期時間}-remote/`（`d1.sql`＋`manifest.json`），照片累積在 `R2-remote/`
- 部署時 `deploy.sh` 在套遷移前會自動備份一次
- `manifest.json` 的 `shrunk` 列出筆數變少的表：軟刪除不會讓筆數變少，有東西變少要查（永久刪除空頁面、清過期 session 屬正常）
- 還原演練（建議每季）：`node scripts/restore.mjs <備份>/d1.sql --local --persist-to <空資料夾>`，再比對 `manifest.json` 的筆數

## 八、出事時

| 狀況 | 做法 |
|---|---|
| 新版程式有問題 | `npx wrangler rollback --config wrangler.production.jsonc` 回上一版 |
| 資料被改壞（7 天內） | D1 Time Travel：`npx wrangler d1 time-travel info yinzang`，再 `npx wrangler d1 time-travel restore yinzang --timestamp=<UNIX 時間>`。**會原地覆蓋整個資料庫**，還原後會給前一個書籤可以反悔。免費方案只能回 7 天（[D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)） |
| 超過 7 天 | 從站外備份還原到**新建的** D1：`npx wrangler d1 create yinzang-restore` → `node scripts/restore.mjs <d1.sql> --remote --database yinzang-restore` → 確認後把 `wrangler.production.jsonc` 的 `database_id` 換過去再部署 |
| 花費警報 | 後台「網站狀態」確認暫停模式；查 R2 用量；必要時手動暫停 |
