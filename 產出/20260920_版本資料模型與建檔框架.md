# 版本資料模型與建檔框架（第一版）

**日期**：2026-09-20  
**用途**：先定義一般使用者能理解的收藏建檔方式，再用 20 件真實收藏驗證。這不是正式資料庫 schema 或完整 MVP 規格。

## 一、設計目標

1. 使用者先找到既有版本，再建立自己的收藏紀錄；只有找不到時才新增版本。
2. 把「作品」、「發行版本」與「個人持有的實體」分開，避免版本資料被品況或個人故事污染。
3. 首次建檔只要求足以辨認版本的資訊，不要求一般使用者一次填完所有專業欄位。
4. 無法確認的資料可以標示待查證，不用猜測。
5. 同一套核心結構先支援音樂載體；服飾、海報、器材等周邊日後用類別模板擴充。

## 二、資料層級

| 層級 | 代表什麼 | 例子 | 不應放入 |
|---|---|---|---|
| 音樂人 | 發行或演出的主體 | 草東沒有派對 | 某張專輯的條碼 |
| 作品 | 抽象的創作／商品系列 | 《醜奴兒》 | 台灣首版、再版 |
| 發行版本 | 可被多人共同辨認的特定版本 | 2016 台灣 CD 首版 | 某位收藏者的刮痕 |
| 個人收藏品 | 某位使用者手上的實體 | 我的那一張 CD | 全體共用的版本年份 |
| 市場紀錄 | 與某件實體或版本相關的交易事件 | 2026-09 成交 NT$800 | 作品的正式名稱 |

關係如下：

`音樂人 → 作品 → 發行版本 → 個人收藏品 → 刊登／成交紀錄`

一個作品可以有多個版本；一個版本可以被多人收藏；每位收藏者手上的品況、購買時間、照片與公開設定可以不同。

## 三、第一輪測試範圍

先以具有較明確識別資訊的音樂載體為主：CD、黑膠、卡帶、DVD、Blu-ray。服飾、海報、簽名品及其他周邊先記錄為測試案例，但不假設它們能完全沿用音樂載體欄位。

## 四、版本建立的最低門檻

建立新版本時，最低必填：

- 音樂人
- 作品名稱
- 商品類別／格式
- 至少一項版本線索
- 使用者認為它可能是不同版本的理由
- 資料狀態

「版本線索」至少提供一項：條碼、目錄號／品號、發行年份、地區、發行／授權單位、封面或包裝差異、碟面／標籤差異、內容物／特典差異。

若只有品況、簽名、編號貼紙、收藏者自己的附件或包裝損傷不同，原則上不是新版本，應記在個人收藏品。

## 五、版本判定規則（第一版）

### 通常應建立不同版本

- 條碼或目錄號／品號不同，且可合理確認不是單純登錄錯誤。
- 發行地區、發行公司或授權單位不同。
- 再版、重製版、紀念版或正式限定版。
- 官方包裝、封面、碟面、曲目或隨附內容物有制度性差異。
- 官方通路、活動或贊助方案造成可重複辨識的版本差異。

### 通常不建立不同版本

- 只有保存狀況不同。
- 只有單件簽名、手寫編號或前持有人註記不同。
- 只有賣家自行搭售的物品不同。
- 外層塑膠膜、價格貼紙或物流包材不同，且不是官方版本設計的一部分。

### 無法判斷時

先建立「待確認候選版本」，記錄差異線索與照片需求。不要硬併入既有版本，也不要直接宣稱為正式新版本。

## 六、欄位分組

### A. 作品層

| 欄位 | 首次建檔 | 說明 |
|---|---|---|
| 音樂人 | 必填 | 可先填主要音樂人；合輯另標示 |
| 作品名稱 | 必填 | 以實物或官方標示為準 |
| 作品類型 | 必填 | 專輯、EP、單曲、合輯、現場、影像等 |
| 首次發行年 | 選填 | 指作品首次公開發行，不等於手上版本年份 |

### B. 發行版本層

| 欄位 | 首次建檔 | 說明 |
|---|---|---|
| 商品類別／格式 | 必填 | CD、黑膠、卡帶、DVD、Blu-ray 等 |
| 版本名稱 | 系統建議 | 由年份、地區、格式與版本特徵組合成人類可讀名稱 |
| 發行年份 | 建議 | 不確定時可只填年代或留白並標待查證 |
| 發行地區 | 建議 | 依實物、公司資料或可信來源判斷 |
| 發行公司 | 選填 | 實際發行者 |
| 授權單位 | 選填 | 與發行公司分開 |
| 條碼 | 建議 | 保留前導零，視為文字識別碼 |
| 目錄號／品號 | 建議 | 可能比條碼更能辨認版本 |
| ISRC | 選填 | 屬錄音識別，不一定能唯一辨認實體版本 |
| 版本類型 | 必填 | 正式、限定、贈品、宣傳、樣品、待確認 |
| 包裝形式 | 選填 | 塑膠盒、紙套、盒裝、開門式等 |
| 內容物／特典 | 選填 | 僅記官方隨附內容 |
| 版本辨識方式 | 必填 | 用一般人能實際比對的文字描述 |
| 資料來源 | 建議 | 實物查證、官方頁面或其他來源 |
| 資料狀態 | 必填 | 待確認、已初步確認、已確認、有爭議 |

### C. 個人收藏品層

| 欄位 | 首次建檔 | 說明 |
|---|---|---|
| 收藏狀態 | 必填 | 我有、想要、曾擁有 |
| 品況 | 我有時建議 | 媒體與包裝可分開評估，第一輪先用文字 |
| 完整度 | 選填 | 是否缺少歌詞本、側標、特典等 |
| 個人備註 | 選填 | 購得故事、瑕疵位置、收藏原因 |
| 照片公開範圍 | 有照片時必填 | 私人、收藏頁公開、同意作版本資料圖 |
| 是否願意出售／交換 | 選填 | 不等於正式刊登 |

### D. 驗證紀錄

這些欄位只用於 20 件測試，不是正式產品資料：建檔日期、花費分鐘、最難填欄位、缺少欄位、是否找到既有版本、是否需要協助、完成後是否願意再建一筆。

## 七、一般使用者建檔流程

1. 搜尋音樂人與作品。
2. 用格式、年份、條碼／品號及外觀差異縮小版本。
3. 找到正確版本後，直接標記「我有／想要／曾擁有」。
4. 找不到時，系統顯示相似版本，要求使用者指出差異。
5. 差異足夠時提交新版本；不足時建立待確認候選版本。
6. 使用者再填個人品況、完整度、照片與公開範圍。

關鍵原則：使用者不必先理解資料庫結構。介面應用問題引導，例如「你看到條碼嗎？」、「外盒和這個版本相同嗎？」、「差異只在品況，還是官方包裝本身不同？」

## 八、20 件實物測試方式

每件收藏都記錄：

1. 是否能在三分鐘內找到或辨認版本。
2. 哪個欄位最先卡住。
3. 是否必須查網路才能完成。
4. 哪些欄位無法從實物判斷。
5. 是否曾想建立新版本，但其實只是個人物件差異。
6. 完成一筆共花幾分鐘。
7. 完成後是否願意再建下一筆。

測完 20 件後，再決定必填欄位、版本判定規則與第一個支援品類，不在測試前把 schema 鎖死。

## 九、目前未解決

- 「作品」與「商品系列」是否足以同時支援專輯與非音樂周邊。
- 合輯、多人合作、不同語言標題及藝人改名的處理方式。
- 服飾尺寸、海報尺寸、巡演場次等類別專屬欄位。
- 條碼相同但包裝或內容物不同時，何種差異才足以拆成版本。
- 資料狀態由誰提升，以及需要幾項獨立證據。
- 正式營運前的圖片授權、權利人通知與下架流程仍需律師確認。
