國蛋《Dr. Paper Vol.3》2016 CD，版本 id 16。MusicBrainz 的對應 release 有對上這個版本，但整列不碰，也沒寫 MBID。匯入前後 `shares` 第 3 則整列、版本 16 的原有欄位逐欄比對都相同，新欄位維持預設值。

## 網站顯示

- 版本區塊的「曲目」預設收合，點開才列；多碟分開列（「第 1 碟 CD」「第 2 碟 CD」）
- 系列頁的「曲目」區塊：版本名稱有「一般版／標準版」就用那個版本，判斷不出來就用最早的實體版本，並註明依哪個版本
- 版本比較表多一列「曲目差異」，對照的基準就是系列頁用的那個版本。先比歌名（簡繁、大小寫、標點都視為相同），歌名對不上的再用時長配對，差 2 秒以內算同一首，因為 MusicBrainz 常一版登中文歌名、另一版登英文歌名。多出來的連號寫成「多了第 14～16 首〈…〉」，超過 3 首只列前 3 首
- 來源：曲目由 MusicBrainz 帶入的顯示「來源：MusicBrainz」，連到該 release 頁；有人改過就接著顯示修改者和日期
- 編輯：走既有的維基式編輯，一行一首，多碟另起一行寫【第 2 碟 CD】。歷史頁 `/artist/{藝人}/{號}/history?tracks={品項}-{版本}`，可以比對、還原
- 計分：原本空白的曲目補上算「補缺漏資料」+10，補自己建的版本不算；改既有曲目算編輯，規則跟正文相同
- 目錄號、條碼照舊只給登入會員看（在辨識細節裡），公開頁面沒有
- 曲目不放進整包目錄，系列頁另外查，免得每次重建目錄多吃 CPU

## 照片上傳框（手機虛線）

`.drop` 改成明確給 `width: 100%`、`box-sizing: border-box`，不再靠 aspect-ratio 反推寬度。手機（700px 以下）拿掉 `max-width: 360px`，框撐滿正文寬度。

本機 Chromium 在修正前量不到裁切，iOS Safari 的 WebKit 這台 WSL 裝不起來，所以真機上是不是這個原因沒有直接驗證。修正後本機與正式站在 320／360／375／390／414 五個寬度，框的左右緣都在畫面內、跟正文左右緣差 0px，左右邊框都是虛線。單則頁「編輯照片」也用同一個元件，320、390 下撐滿編輯框內緣。截圖在 `img/上傳框_*.jpg`、`img/編輯照片_*.jpg`。大頭貼上傳用的是另一個按鈕，沒有虛線框，不受影響。

🟡 請用手機再看一次 `/share/new`，確認左右虛線都在。

## 怎麼重跑

```
cd 網站
node scripts/import-musicbrainz.mjs --fetch-only              # 只抓資料、做藝人對應（有快取就不重抓）
node scripts/import-musicbrainz.mjs --local --dry-run          # 看計畫與 SQL，不寫入
node scripts/import-musicbrainz.mjs --remote                   # 正式站：先自動備份，失敗就停
```

- 遵守 MusicBrainz 規則：User-Agent `Lemicang/0.1 ( zukawork0312@gmail.com )`，每秒最多 1 次請求，503 會退避重試。回應存在 `網站/.cache/musicbrainz/`，已加進 `.gitignore`。第一次抓約 70 次請求
- 每筆寫入都帶 `source='musicbrainz'`（新建的）或 MBID（合併的），所以重跑不會重複建
- 腳本：`網站/scripts/import-musicbrainz.mjs`（主程式）、`musicbrainz-fetch.mjs`（抓取與藝人對應）、`import-musicbrainz-db.mjs`（寫資料庫）

## 已知情況

- MusicBrainz 有些版本登的是簡體或英文歌名（例如收斂水 2009 CD、差不多先生標準版），系列頁的代表曲目就照登錄的樣子顯示，沒有自動轉換。會員可以直接改，改了會顯示修改者
- 有 1 個版本 MusicBrainz 沒登發行日期，版本名稱就只有「台灣 CD」（張震嶽《有問題》第 2 版）
- 夜貓組《健康歌曲》：MusicBrainz 是 2017 CD，研究裡是 2024 黑膠。年份不同，照「名稱加年份」規則沒有合併，所以現在有兩個系列。研究 README 原本就寫「關係待確認」
- 版本名稱的「首版」只給發行年等於該專輯最早發行年、而且是該地區最早的一筆；晚於最早發行年的標「再版」
