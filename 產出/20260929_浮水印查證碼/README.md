## 2. 查證碼

- 5 碼，字元 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`（31 個，排除 0 O 1 I L），約 2,860 萬組，拒絕取樣產生
- 發號：瀏覽器燒浮水印前先打 `POST /api/uploads/code`，伺服器寫進 `photo_codes`（碼是主鍵，發過的不會再發），每人每天 90 組
- 上傳：`/api/uploads` 收藏照片必帶 `code`。伺服器用一句條件式 UPDATE 佔用（發給這個人、還沒用過才成功），佔到才寫 R2，最後寫進 `photos.verify_code`（唯一索引）。別人的碼、用過的碼、沒發過的碼一律 409；沒帶碼的舊版頁面 400「網頁版本太舊，重新整理再上傳」
- 單則頁照片下方顯示「查證碼 #XXXXX」，連到 `/verify?c=XXXXX`；多張時跟著目前那張換。被檢舉鎖定的收藏不顯示
- 限制：浮水印是瀏覽器燒的，伺服器驗不出圖上印的碼是不是發給它的那組。刻意改前端程式的人可以在自己的照片上印別的字，但查證頁只會回報碼登記的那則收藏，冒用不了別人的碼

## 3. 查證頁 `/verify`

- 輸入框＋「查詢」，GET 表單，`/verify?c=A3F9K` 直接帶碼也能查；輸入小寫、前面帶 # 都接受
- 查到：縮圖（這張照片自己的縮圖）、查證碼、收藏標題（連單則頁）、發文者「暱稱 @帳號」（連個人頁）、發布日期（台灣時間）
- 查無（碼不存在、格式不對、照片沒掛上收藏）：只顯示「查無此查證碼」
- 露出多少（做法）：
  - 收藏被隱藏或刪除：「這張照片來自樂迷藏會員 @帳號，收藏已下架」，不給縮圖、標題、日期，也不連個人頁
  - 收藏還在、這張照片被刪：「這張照片來自樂迷藏會員 @帳號，照片已下架」
  - 發文者已刪帳號、收藏還在：照常顯示收藏，發文者欄寫「已刪除的會員」、不連結、不露 `del-` 代號
  - 發文者已刪帳號、收藏也下架：「這張照片來自已刪除的會員，收藏已下架」
  - 被檢舉鎖定的收藏：站內本來就照常可看，查證頁照常顯示
- 限流：同一 IP 每小時 30 次（`rate_limits` 的 `verify:IP`，跟註冊、重寄驗證碼同一套），超過顯示「查詢次數太多，一小時後再查」，連真的碼也不回結果。只開頁面、沒帶碼不算次數
- 不進整頁快取（`worker.ts` 的 `CACHEABLE` 沒列）
- 入口：頁尾「關於樂迷藏」後面加「照片查證」
