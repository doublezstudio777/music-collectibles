## 本輪做了什麼

1. **2a 遺留**：`/api/auth/forgot-password` 每 IP 每小時 10 次、每 Email 每小時 5 次；`/settings` 做出來（改顯示名稱、改密碼〔其他裝置登出〕、登出所有裝置、刪除帳號申請）；頭像選單「設定」連過去，「管理後台」只有管理員看得到，舊的「檢舉示範身分」切換拿掉
2. **內容表進 D1**（`drizzle/0001_content.sql`，全是新表）：藝人、系列、品項、版本、正版辨識、已知仿冒、炫收藏、照片、出價、對話、訊息、已讀、檢舉、申訴、裁決、設定、管理紀錄、計數器。示範內容搬到 `網站/scripts/demo-data.ts`，只有 `npm run db:seed:local` 用
3. **存在性檢查**：點讚、我有、想要、追蹤打開時查對象存不存在（404）；**讚數、持有人數**改成資料庫實際計數（頁面給「其他人」的數，登入者自己那一下前端疊）
4. **炫收藏發布走 API**，作者是登入的人；必填照舊（照片、系列＋品項或類型、跟誰有關）
5. **照片上傳 R2**：瀏覽器端壓縮、伺服器看檔頭＋大小、每人每日 30 張、總容量 8GB（D1 計數器先佔額度）、`/img/...` 一年快取
6. **出價、私訊、成交、撤回、拒絕、改回出售中**全走 API，權限在伺服器判斷；鎖定判斷只有一份（`lib/data.ts` 的 `lockFor`），頁面與 API 共用
7. **檢舉**：已驗證 Email 才能送、一人一次（資料庫唯一鍵）、門檻計數在資料庫
8. **申訴與管理後台**：`/admin` 頁面與 API 兩邊擋，管理員名單看環境變數 `ADMIN_EMAILS`（本機 `admin@demo.yinzang.test`／`yinzang-demo`）；解鎖、維持鎖定、調門檻、核准新增都寫 `admin_log`
9. **這裡沒有，我要新增**：藝人、系列、品項（帶一個版本）、版本，送出後待審核，後台核准才出現
10. **藝人匯入腳本** `網站/scripts/import-artists.mjs`：這輪寫死本機、拒絕 `--remote`；藝人頁有維基簡介時顯示「來源：維基百科」＋條目連結＋CC BY-SA 4.0
11. 設計文件補第十五～十七節（刪除帳號策略、上傳上限、跟原規劃的差異）

## 已知問題與取捨

1. **295 位藝人沒有網址識別碼**：名單只有 31 位有英文名。slug 一經建立不改，所以沒給臨時值，列在 `網站/.wrangler/import-artists-待補.csv`（本機產物，不進 repo）。要使用者決定怎麼補（見回報）
2. 維基簡介.csv 沒有授權、擷取日期欄，腳本預設「CC BY-SA 4.0」與匯入當天
3. 內容一個請求整包讀出來在記憶體查（藝人、系列、所有炫收藏、所有使用者名稱）。朋友測試期夠用；量大後要改成分頁查詢，首頁的「追蹤中／只看在賣」也要搬進 SQL
4. 表單的藝人一次最多列 30 位，其餘靠分類或打字搜尋（名單三百多位全部攤開太長）
5. 表單只放一張照片；API 收 1～6 張。多張的畫面還沒做
6. 上傳了但沒發布的照片會留在 R2、算進容量（孤兒照片清理列 2c）
7. 申訴證據照片跟一般照片走同一個 `/img/` 路徑，網址是隨機 id 但不是只有管理員看得到
8. vinext 會把所有 multipart POST 先當 server action 檢查大小（預設 1MB），`next.config.ts` 放寬到 2MB 才讓 1.5MB 的主圖進得來
9. 刪除帳號只做「申請」，實際刪除策略寫在設計文件第十五節，**需要使用者確認**
10. 新增品項會一起送一個待審的版本，管理員要兩筆都核准才出現；後台沒有「一起核准」按鈕
11. 系列、藝人被退回後網址識別碼（slug、流水號）仍佔著，不會重用
12. 驗收時為了測 IP 級頻率限制，用 `cf-connecting-ip` 表頭假造 IP（本機可偽造，2a 獨立驗收已列為 2c 部署前檢查項）
13. 驗收帳號、炫收藏、出價都寫進本機 `.wrangler/state`，每跑一次多一組（本機資料，不影響正式）；本機也匯入了 31 位真藝人
14. `components/local-share.tsx` 已不再使用，內容清成空模組；照刪檔規則沒刪，等使用者確認
15. 首頁「追蹤中」沒登入或還沒追蹤時上方的熱門藝人，以跟誰有關／標籤撞名的收藏數排序，跟 2a 相同
16. 已售出改回出售中時，原本成交那筆出價標成「已撤回」，紀錄留著
