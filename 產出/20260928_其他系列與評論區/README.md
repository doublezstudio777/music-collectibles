## 已知問題與取捨

1. 留言檢舉另存 `comment_reports`，沒放進 `reports`：`reports` 掛了內容版本觸發器，放進去每次檢舉留言都會讓全站快取失效。API 入口共用 `/api/reports`，後台是獨立的「被檢舉的留言」區，不在原本的「檢舉」表格裡
2. 自動隱藏門檻預設 3，跟收藏鎖定的門檻（10）分開設。留言成本低，10 人太慢
3. 「等 N 位」的 N 取總人數（中文「甲、乙等 12 位」的慣用讀法），不是「另外 N 位」。標題旁的數字也是總人數
4. 貢獻次數：正文每一筆修改都算（含還原），品項、版本只算已核准且沒被隱藏的，炫收藏只算沒被隱藏、沒刪除的。待審與被退回的不算
5. 系列沒有真正的封面資料，封面借用收藏者照片的縮圖；被鎖定的收藏照片不拿來當封面。之後有封面欄位再換
6. 留言最多載入最新 200 則，沒有分頁
7. 站外交易字眼是關鍵字比對，會有誤判（例：留言裡提到正常的「轉帳」、@ 某人），也會漏網（諧音、拆字）。只提醒不擋，影響有限
8. 留言不在頁面 HTML 裡，搜尋引擎與連結預覽看不到留言（目前整站 noindex）
9. 管理員調整留言門檻會寫 `settings`，這張表有內容版本觸發器，會讓快取換一次。管理員偶爾才調，沒有另外處理
10. 未驗證 Email 的帳號本來就登不進來；伺服器端仍然檢查，驗收用改資料庫模擬
11. 留言停權只是不顯示，資料保留；刪除一律軟刪除，留言者不會收到通知
12. 留言不能編輯，只能刪掉重寫
13. 頻率限制先扣每分鐘再扣每天；被每天上限擋掉的那次仍算進每分鐘的額度，差別很小沒處理
14. `上線後第一批` 舊腳本第一次跑 64/65：它挑「最新一則有照片的收藏」測清快取，剛好挑到前一支腳本（預覽圖）剛建、分享預覽圖已被讀過的那則，清掉 3 個檔（主圖、縮圖、預覽圖）而不是 2 個，行為正確是期望值寫死 2。單獨重跑 65/65，跟這批改動無關
15. 版權聲明的文字正式上線前要給律師確認（決策檔原本就這樣寫）
16. `SPONSOR_URL` 要設時，加在 `wrangler.production.jsonc` 的 `vars` 後照 `deploy.sh` 部署，只接受 https 網址，格式不對一樣不顯示
17. 系列頁沒命中時多一個查詢（貢獻者），實測 CPU 跟其他頁面同量級；免費方案 10ms 上限的問題仍在（沒命中本來就超過），這批沒有讓它更嚴重
