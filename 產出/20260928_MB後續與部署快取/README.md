### 「打字選新藝人」找不到選項的原因

腳本只打了藝人名稱的前 6 個字「表單新選藝人」。本機之前每跑一次就會多建一位「表單新選藝人{時間戳}」，已經累積 12 位同樣開頭的藝人。新表單的搜尋建議最多只列 5 個，搜尋 API 又是照目錄原本的順序回前 20 個，所以這次新建的那位排不進前 5 個，點不到。

這主要是測試資料累積造成的，但也順便看出新表單的一個缺點：建議清單沒有依相關程度排序。只要有超過 5 位藝人的名字包含你打的字，就算你打的是完整名字，那一位也可能被擠到清單外面。修法是 API 和表單都改成依「名稱或別名完全相同 → 開頭相同 → 包含」排序，完整名字一定排第一（`app/api/artists/search/route.ts`、`components/share-form.tsx`）。改寫後的腳本打完整名字再用 `data-slug` 點選；判斷「選到後畫面上只有這一位」沒有改，只是檢查的節點從 chip 換成答案黑框 `bar-about`。

## 3. 部署後煙霧測試的暫時性錯誤

### 原因

新版本部署出去後，舊版本在一段時間內還會繼續回應，回出來的是指向上一版 JS／CSS 的 HTML。可是上一版的資產在新版本上線的同時就不見了（回 404），瀏覽器載入這種頁面時，每個改過檔名的 chunk 都會報一次錯。

一開始懷疑的是整頁快取。不過快取鍵本來就含部署版本（`worker.ts` 用 `CF_VERSION_METADATA.id`），新版本不會讀到舊鍵，所以問題不在快取鍵，而是舊版本自己還在服務。以下是證據：

1. **舊資產在切換時立刻消失**：第 1 次部署（還沒修）時，一抓到新版 HTML，上一版 HTML 用到、新版沒有的 17 個資產裡已經有 15 個回 404，另外 2 個還是 200。可見資產是一台一台切換的，不是同時切（`部署探測/部署_d1_資產探測.log`）
2. **部署完成後，舊版本還在回 HTML**：第 3 次部署時，wrangler 一印出 `Current Version ID: cbba13a7`，馬上開瀏覽器跑一次煙霧測試，拿到的首頁表頭是 `x-yz-build=450ebe12`，也就是上一版（`部署探測/部署_d3_提早煙霧測試.log`）。那次沒有報錯，是因為修法已經上線，上一版的資產還在
3. **數量對得上**：每次建置大約有 54～58 個前端檔的檔名會變，首頁引用的有十幾個，跟之前每次報 14～16 筆 console error 相符

這個問題不只影響測試。部署後幾十秒內打開網站的真人，也可能拿到舊版本的 HTML，頁面上的互動全部壞掉。部署前就開著頁面的人，部署後點站內連結時會延遲載入舊的 chunk，一樣會 404。

### 修法：保留上一版資產（選第二個方案）

沒有選「快取鍵加部署版本」，因為快取鍵本來就有部署版本，問題也不是快取造成的。舊版本在退場前送出的 HTML，只有保留舊資產才救得回來。

- `網站/scripts/keep-assets.mjs`：建置完、部署前，先把 7 天內曾經在線上的舊檔補進 `dist/client`（`merge`）；部署成功後，把這次建置的檔案存進 `網站/.deploy-assets/`（`save`，不進 git），超過 7 天的就移除。檔名都帶雜湊，新舊檔不會撞名。`deploy.sh` 會自己呼叫
- `worker.ts`：整頁快取的頁面加上 `x-yz-build` 表頭（部署版本前 8 碼），之後可以直接分辨一個回應是新版本還是舊版本送的
- `網站/scripts/wait-live.py`（`deploy.sh` 第 6b 步）：部署後每秒抓一次首頁，要連續 3 次都由新版本回應、首頁引用的資產也全部是 200，才進入瀏覽器煙霧測試；等待期間看到的舊版本回應或 404 會逐筆印出。90 秒內沒有穩定下來，部署就算失敗
- `scripts/smoke-browser.py`：失敗時逐筆列出錯誤，console error 附來源網址和行號，每個 400 以上的回應都列出網址、狀態、資源類型、`x-yz-cache`／`cf-cache-status`，首頁另外列 `x-yz-build`

限制：存檔在執行部署的那台電腦上。換一台電腦（例如 Mac）部署的第一次，存檔是空的，只會有新檔。另外 Workers 免費方案每個版本的上限是 20,000 個檔，目前每次部署約 58 個檔，7 天內部署幾十次也遠低於上限。

### 修正後連續部署

| 部署 | Version | 第 7 步第一次煙霧測試 | 提早煙霧測試（剛部署完馬上跑） | 高頻探測（每 0.4 秒抓首頁，每秒查新舊資產） |
|---|---|---|---|---|
| 第 2 次（保留資產） | `450ebe12` | console error 0、HTTP 錯誤 0 | 0 錯 | 舊資產全程 200 |
| 第 3 次（加上等待新版本生效） | `cbba13a7` | console error 0、HTTP 錯誤 0 | 0 錯（拿到的是上一版 `450ebe12` 的 HTML，資產都還在） | 新舊資產全程 200，沒有 404 |
| 第 4 次 | `315b5413` | console error 0、HTTP 錯誤 0 | 0 錯 | 新舊資產全程 200，沒有 404 |

第 3、4 次是修法完整之後的兩次部署，第一次跑煙霧測試就是 0 錯。等待新版本生效分別花了 35 秒、33 秒，期間沒有看到 404。提早煙霧測試只有一筆 `?_rsc` 請求 `ERR_ABORTED`，那是點連結換頁時瀏覽器取消了預先載入，不算錯誤，也不計入 console error。
