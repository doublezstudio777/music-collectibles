## 必修 7 項

### 1. 404 是框架預設的英文頁，iPhone 深色模式整頁變黑
- 網址：任何不存在的網址，含被刪除的收藏 `/share/99999`、`/artist/nobody`、`/u/nobody`、`/artist/hyukoh/999`｜寬度 390、1440
- 頁面標題是「404: This page could not be found.」，內文英文、字型 system-ui。框架預設樣式帶 `prefers-color-scheme: dark`，iPhone 開深色模式時內容區變全黑，**頁首的站名、搜尋、登入一起變白字消失**（頁首是白底）
- 開放收錄後，刪除的收藏、改過網址的藝人都會從 Google 進到這頁
- 改法：自訂 `app/not-found.tsx`，沿用站內版型，一句「找不到這一頁」＋回首頁、看全部藝人兩個連結
- 截圖 `img/設計_01_404_淺色與深色_390.jpg`

### 2.「我要買」按一下就送出，沒有確認，也沒說接下來怎麼走
- 網址：定價出售的單則頁，例 `/share/9`｜390
- 按下去直接建立「我要買 NT$ 680 等回覆」並跳到私訊，中間沒有任何確認。誤觸一次，賣家就收到購買通知。畫面也沒告訴買家「賣家接受後，你們在私訊約面交或轉帳」
- 賣家那邊同樣一鍵：出價列表的「拒絕」「成交給這位」按了立刻生效（`components/share-detail.tsx` 720～733 行）
- 改法：「我要買」按了先展開跟出價一樣的小框，寫價格＋一句之後的流程＋「確定要買」主按鈕；「拒絕」「成交給這位」加一步確認
- 截圖 `img/設計_02_我要買一鍵送出_390.jpg`、`img/設計_10_單則頁路徑列與出價列表_390.jpg`

### 3. 後台三個不可逆或影響全站的操作沒有確認

### 4. 炫收藏表單的照片排序鈕大小不一、太小

- 量測：第一張的 ◀ ▶ × 是 38×32px，第二張起變 28×42px，「設封面」塞在 28px 寬裡斷成「設封／面」兩行。兩排按鈕高度不同、寬度都低於 40px

- 截圖 `img/設計_05_版本比較列高不一_1440.jpg`

### 6. 標題的 `text-wrap: balance` 在 iPhone 造成提早換行、右側空白
- 網址：首頁、個人頁、藝人頁的收藏卡片；系列頁、單則頁標題｜390
- `app/globals.css` 98 行 `h1, h2, h3 { text-wrap: balance; }`。卡片標題是 h3，「關掉／打開・2022 台灣首版 CD」在 170px 寬的卡片放得下前半「關掉／打開・2022」，WebKit 為了平衡兩行，在「・」後就換行，第一行右邊空一大塊。系列頁標題「2017《23》／專輯發行」也是同一原因
- 跟 10/01 修掉的 `p { text-wrap: pretty }` 同一類：Chromium 看不出來，iPhone 才明顯
- 改法：`.card-title` 改 `text-wrap: wrap`；h1 是否保留 balance 交給使用者看實機
- 截圖 `img/設計_06_卡片標題提早換行_390.jpg`

### 7. 系列頁把內部欄位名稱給訪客看

## 建議 22 項

### 頁首與全站一致性

**S1. 頁首按鈕大小不一**（全站登入狀態｜390／375／320）
炫收藏 44px 高、頭像 40×40；389 以下炫收藏縮成「＋」是 40×44，不是 DESIGN 寫的方塊。頭像在頁首顯示兩行多字暱稱（「UX檢／查甲」），頁內同一人是首字黑方塊「U」，兩套樣子。建議頁首四個圖示鈕、炫收藏、頭像統一 40×40（炫收藏寬度另計），頭像改回首字。截圖 `img/設計_07_頁首登入狀態_390_375_320.jpg`

**S2. 同一件事三種說法**
- 在賣：首頁「只看在賣」、系列頁分頁「在賣的」、願望清單「有 N 件出售中」。建議統一「出售中」
- 合集：按鈕「發合集」、表單欄位「合照」、驗證訊息「放一張合照」、DESIGN 叫「全家福合集」。建議表單一律「合集照片」
- 必填：炫收藏表單寫「前兩題必答」，但黏底列說「還差 3 題：照片、誰的東西、是什麼」，新手指南寫「必填：照片、藝人、品項」。建議表單標題列改成「照片、誰的東西、是什麼 必填」，指南跟著改
- 私訊頁標題 16px 小字，願望清單、設定是 28px 大標
截圖 `img/設計_18_合集與一起發文_390.jpg`、`img/設計_17_私訊列表與對話_390.jpg`

**S3. 系列頁的「複製連結／編輯／歷史」跟藝人頁不一致**（`/artist/hyukoh/1`｜390）
藝人頁 10/01 改成小字連結，系列頁仍是三顆框線按鈕，在手機頭部佔一整排。建議跟藝人頁一樣。截圖 `img/設計_05b_系列頁首屏_390.jpg`

**S4. 後台出現第四種按鈕**（`/admin/artist-photos`｜1440）
「撤下」是黑底實心，DESIGN 的按鈕只有主、次、文字三層。建議改次按鈕。

### 交易與私訊

**S5. 單則頁的路徑列像麵包屑，下面又重複一次**（`/share/9`、`/share/8`｜390）
「男孩 › CD › 2015 台灣首版 CD」是一整條連結，沒說連去哪；下一行孤立的「CD」跟它重複。DESIGN 禁用清單有麵包屑。建議改成「收錄在 男孩《2015 台灣首版 CD》」一句，有連結時拿掉下面的類型行。截圖 `img/設計_10_單則頁路徑列與出價列表_390.jpg`

**S6. 出價列表的狀態長得像按鈕**（賣家看 `/share/8`｜390）
「等回覆」是 1px 框小方塊，緊貼「接受」「拒絕」兩顆框線按鈕，第一次看會以為可以按。建議狀態改純灰字或灰底無框。

**S7. 私訊對話頂端把價格截掉**（`/messages/{id}`｜390）
「賣家 UX檢查甲・所在地區 台灣・定價出售 NT$ …」最重要的價格被省略號切掉。建議拆兩行，價格放第一行標題右側。輸入框是單行 input，問細節常要寫一段，建議改可長高的多行框；送出出價後只出現「已更新」三字，建議寫「已送出出價 NT$ 300」。截圖 `img/設計_17_私訊列表與對話_390.jpg`

**S8. 未驗證 Email 的會員能按「我要買」，卻不能傳訊息**（新會員看 `/share/9`｜390）
單則頁寫「驗證 Email 後才能私訊」，但「我要買」照樣送出成功，進到對話又是「驗證 Email 後才能傳訊息」。買家送了購買意願卻無法回賣家。哪一邊放寬交給產品顧問判斷，介面上至少要一致。截圖 `img/設計_17_私訊列表與對話_390.jpg` 第三張

### 發文流程

**S9. 炫收藏表單黏底列太高**（`/share/new`、`/share/batch`、`/share/collection`｜390）
量測 142px，佔 iPhone 畫面 17%；其中三行是 CC 授權說明，每次發文都一直在。建議說明縮成一行「發布即同意 CC BY-NC-ND 授權　詳細」，或只在這個帳號第一次發布時完整顯示。截圖 `img/設計_08_炫收藏表單黏底列_390.jpg`

**S10. 發布成功沒有回饋**（`/share/new` → 單則頁｜390）
發布後直接換到單則頁，沒有任何「發好了」的訊息。一起發文有結果盒，單則發文沒有，建議單則頁頂端出現一次性的「已發布」灰底條，附「再發一則」。

**S11. 一起發文空狀態是死路**（`/share/batch` 直接打開｜390）
「沒有要發的收藏」旁只有「我的頁面」按鈕。建議改成「先到藝人頁的『我收藏了哪些』勾選」並連到最近看過或追蹤的藝人。截圖 `img/設計_18_合集與一起發文_390.jpg`

**S12. 炫收藏表單「誰的東西」藝人下面重複一次大寫英文名**（`/share/new`｜390）
選好 Hyukoh 後顯示「Hyukoh／HYUKOH」，別名跟本名只差大小寫時建議不顯示。

### 新手與個人頁

**S13. 我的頁面空狀態沒有下一步，分數行斷出孤字**（`/u/{自己}`｜390）
「我有　還沒有標記」「願望清單 0　還沒有標記」沒說怎麼加；「標記」也不是站上其他地方的說法。分數行在 390 寬斷成「…還差 20／分」「（每天統計一／次）」。建議空狀態各給一個連結（「到藝人頁勾我收藏了哪些」「在版本旁按愛心加入」），分數行拆成兩行固定內容。截圖 `img/設計_12b_我的頁面空狀態_390.jpg`
