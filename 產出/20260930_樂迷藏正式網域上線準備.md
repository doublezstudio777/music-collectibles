# 樂迷藏正式網域上線準備

日期：2026-09-30。狀態：品牌「樂迷藏」已確認；正式網域待選、未購買、未切換。本文件是執行清單，不代表已部署。

## 目標與現況

使用者希望換正式網域、放自己的收藏並對外上線。現有站在 `https://yinzang.dblzm.workers.dev`，使用 Cloudflare Worker `yinzang`、既有 D1 和 R2；網站已可註冊、登入與發布「炫收藏」。正式網域應接到**同一個 Worker**，不要重建資料庫、照片桶或會員。照片浮水印已是「樂迷藏」；只改網域不需重燒。

## 實際執行順序

1. **選網址**：比較 `lemicang.com`（中文品牌對應）、`lemibox.com`（使用者原構想）等。2026-09-30 Verisign .com RDAP 查 `lemicang.com`、`yuemicang.com`、`lemibox.com` 均為 HTTP 404，代表當下查無註冊資料，非購買保證。付款前於註冊商做最終可註冊與續費價格確認；品牌與近似商標另查智慧財產局。
2. **購買與 DNS**：若用 Cloudflare Registrar，於現有 Cloudflare 帳號購買並完成註冊人 Email 驗證。這樣網域直接在同一 Cloudflare 帳號，可接 Workers Custom Domain。買其他註冊商時，需把網域加入 Cloudflare zone 並按其指示設定 nameserver。
3. **綁正式網域**：先備份 D1/R2，將正式 hostname（例如 apex）綁到既有 `yinzang` Worker；`www` 若要用，另設轉址或綁定。確認 TLS 憑證可用。不要因改網域而建立新的 D1/R2。若用 Wrangler 設定 `routes`，先確認 `YINZANG_DEPLOY=production npm run build` 的 `dist/server/wrangler.json` 有保留路由設定，因 `scripts/deploy.sh` 實際是用這個建置後設定部署。
4. **登入與表單**：Cloudflare Turnstile 現有 widget 加入新 hostname。驗證註冊、登入、忘記密碼、意見回饋、炫收藏上傳。Session cookie 沒設定 `Domain`，換 hostname 後會員需在新網址重新登入，原會員和收藏仍在。若寄信服務需驗證寄件網域，設定新網域的寄件子網域與 DNS 後再測真實信件。
5. **部署驗收**：現有 `網站/scripts/deploy.sh` 寫死 workers.dev 網址和 `noindex` 斷言；在正式網域啟用或把 `ALLOW_INDEXING` 改成 `1` 之前，應讓煙霧測試支援目標網址與兩種收錄狀態，否則可能程式已部署卻在驗收步驟報錯。驗首頁、藝人頁、收藏頁、圖片、查證頁、登入及手機瀏覽；保留舊網址直到轉址驗證完成。
6. **放自己的收藏**：以既有帳號從「炫收藏」流程先發布少量真實收藏，包含唱片、場刊或周邊；檢查照片浮水印、藝人標籤、系列／版本、個人頁與分享網址。不要拿測試物件充數。既有站也能先發布，未來綁同一 Worker 與 D1/R2 後仍在。
7. **開放搜尋收錄**：現行 `ALLOW_INDEXING=0`，Google 等搜尋引擎不收錄。對外分享網址可先做，但若要公開搜尋，先處理法務頁「草稿」標示、瀏覽次數保存期限、刪帳策略，以及 `00_現況.md` 的正式上線前律師確認清單；依專案共用規則，正式營運前請台灣律師審閱。確認舊 workers.dev host 對新網址的轉址與 canonical，再開 `ALLOW_INDEXING=1`，避免兩個 hostname 同時被收錄。
8. **上線後**：確認站外備份排程已真正建立並做一次還原演練；看 Cloudflare 用量、錯誤、Turnstile、註冊信和內容回報。`產出/20260927_部署手冊.md` 有備份步驟，但是否已有每週排程需在 Windows 主力機確認。
