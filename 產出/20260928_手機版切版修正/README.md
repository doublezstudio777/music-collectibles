# 手機版切版修正（2026-09-28）

## 一、原因

用戶截圖 `https://yinzang.dblzm.workers.dev/artist/gordon`（iPhone）：藝人頁「系列」那一區
的卡片在窄螢幕被排成一列橫向捲動（`.tiles { display: flex; overflow-x: auto }`、
`.tile { flex: 0 0 120px }`），第三張以後的卡片被裁在視窗右邊界外，使用者看起來像是
「文字被切掉、版面沒有滿版」，其實是可以側滑但沒有任何提示。

`.tiles` 這個 class 同時是藝人頁「系列」與系列頁「其他系列」共用的元件（`SeriesTile`），
所以兩處會一起中招。

## 二、修了哪些區塊

1. **`app/globals.css` `.tiles`（700px 以下）**：拿掉 `overflow-x: auto` 橫向捲動，改成
   `grid-template-columns: repeat(2, minmax(0, 1fr))` 兩欄格狀；卡片寬度用 grid 自動等寬，
   標題原本就沒有截斷樣式（沒有 `line-clamp`／`text-overflow`），現在會完整換行顯示。
   影響：藝人頁「系列」、系列頁「其他系列」。
2. **版本比較表（`.compare-scroll`）加捲動提示**：這張表在版本多的時候本來就需要橫向捲動
   （kept，因為多欄並排是既定設計），現在加了：
   - 邊緣淡出漸層（CSS-only 雙背景層技巧，`background-attachment: local`，捲到底自然消失，
     不用 JS）
   - 版本超過 2 個時，表格上方多一行「左右滑動看更多版本 →」文字提示（只在 700px 以下顯示）
   影響：系列頁品項下的版本比較表。

## 三、檢查過但沒改的地方（本來就沒問題）

- **首頁熱門藝人排**（`.hot-list`）：700px 以下本來就是單欄 grid（`grid-template-columns:
  minmax(0, 1fr)`），不是橫向捲動，沒有裁切問題
- **首頁炫收藏卡片牆**（`.wall`）：700px 以下本來就是兩欄 grid，標題用 `-webkit-line-clamp: 2`
  兩行後省略號，這是既有設計（首頁卡片本來就不要求標題完整顯示），不是這次回報的 bug，未動
- **系列頁品項列**（`.item-index`）：本來就是 `flex-wrap: wrap`，700px 以下改
  `flex-direction: column` 直排，沒有橫向捲動
- **單則頁照片縮圖列**（`.gallery-track`／`.gallery-strip`）：是刻意的滑動輪播（swipe carousel），
  已經有「1／3」張數提示疊字，不是意外裁切，維持原樣

## 四、檢查方式

Playwright 逐一開 320／360／375／390／414／430／768／1024／1440 九個寬度，四類頁面
（藝人頁、系列頁、首頁、單則頁），用 Range rect 量每個文字節點的實際渲染右緣，比對容器
可視寬度右緣（`line-clamp` 元素排除，那是刻意設計），同時檢查 `.tiles`／`.hot-list`／
`.wall`／`.item-index` 這幾個「不該是捲動容器」的 scrollWidth 是否超出 clientWidth。
腳本：`_檢查.py`（讀 `/tmp` 暫存，已附核心邏輯說明於本檔）。

**結果：9 寬度 × 4 頁面共 36 組，無文字截斷、無非預期橫向捲動、console error 0。**
截圖存 `img/`（`{頁面}_{寬度}.jpg`，例如 `artist_375.jpg`）。額外截了正式站上線後的
`/artist/gordon` 在 390px 的 `.tiles` 區塊（`live_gordon_390.jpg`），跟原始回報截圖同一支
藝人、同一個區塊，確認「2021《Sour》單曲發行」那張卡片完整顯示不再被切。

## 六、已知限制

- 兩欄格狀在 320px 最窄時每張卡片實際寬度約 130px 上下，圖片區塊會比桌機版小很多；這是
  使用者本次明確要求的排法（2 欄格狀），沒有另外對超窄螢幕（<360px）再分 1 欄
- 版本比較表「左右滑動看更多版本」提示只在版本數 > 2 時顯示；2 個版本以下即使在窄螢幕也可能
  需要小幅捲動（128px 固定欄＋2×200px），但機率低，沒有另外處理
