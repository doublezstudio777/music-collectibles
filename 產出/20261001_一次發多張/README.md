## ② 批次發文

- `/share/batch?keys=…`：從「一起發文」帶這次勾的（這次沒勾新的就帶這位藝人全部勾著的）；從合集「挑幾張單獨發文」帶挑的
- 上方先統一選交易狀態（純分享／開放出價／定價出售），每張可以個別改；定價的每張填自己的價格；不在台灣連線時只能純分享（同現行規則）
- 每張：照片（跟炫收藏同一套上傳：瀏覽器燒浮水印、查證碼、不公開原圖，一則最多 10 張）、想說的話、交易狀態；系列層「不確定版本」的那張多一排類型點選
- 發布：一則一則打原本的 `POST /api/shares`，所以同意條款、交易限台灣、每日上限、照片是不是自己剛傳的，全部照現行規則擋；CC 授權提示在發布按鈕上方
- **上限**：先問新的 `/api/shares/quota`（讀 `/api/shares`、`/api/uploads` 實際在用的計數，只讀不寫）。超過今天發文上限（30 則）的那幾張，發布前就整段變灰底、最下面黑底白字「這次發不了：今天還能發 N 則」，不送；發布後結果盒列「發好了」與「這次發不了」＋原因。照片上傳上限（每天 30 張）超過時，那張照片框上直接顯示伺服器的訊息，那一則列成還沒準備好
- **草稿**：存這台瀏覽器 localStorage（每位會員一份）：專輯、說明、交易設定、已經傳好的照片。中途離開再回來會接上（驗收：傳了 3 張後離開，回來照片、說明、個別定價都在）。發好的從草稿拿掉，發不了的留著；「清掉草稿」會順便刪掉伺服器上還沒發的照片

## ③ 全家福合集

- 合集就是一則 `shares`（新欄位 `post_type='collection'`），所以照片、浮水印、查證碼、讚、留言、檢舉（回報入口）、隱藏下架、刪帳重燒、sitemap 全部照一般收藏那一套，沒有另做
- 發文 `/share/collection`（炫收藏頁右上「發合集」、我收藏了哪些底部「發合集」）：照片 1～10 張 → 標記專輯（搜尋藝人 → 同一份勾選清單，可以跨藝人，最多 60 張；一樣有「這裡沒有，我要新增」）→ 想說的話 → 標題選填（自動組「Hyukoh、林俊傑・合集 8 張」）
- 合集頁：照片照原比例；專輯清單每列連到專輯頁（版本層連到版本錨點）；沒有交易區。發文者多一個灰盒：「編輯」「把這些登記成我有」（一次登記，等於 ①）「挑幾張單獨發文」（勾幾張帶去 ②，專輯已選好）
- 純展示：`PATCH /api/shares/{n}` 改狀態回 409 `COLLECTION`，出價回 403／409，一般收藏的編輯 API 也擋合集
- 首頁、個人頁、系列頁卡片：狀態槽位放灰底「合集 8 張」，跟四種出售狀態都不撞
- 被標記的專輯頁：頭部數字列「出現在 N 個合集中」（連到下方）、版本標題旁同一句、頁面下方一塊卡片牆列出合集
- SEO：合集頁可收錄（照一般收藏規則，被檢舉鎖定才不收），title「Hyukoh、林俊傑 收藏合集 8 張｜發文者｜樂迷藏」、description「發文者的收藏合照，裡面有 Hyukoh《23》、林俊傑《對的時間點》…等 8 張。」接說明前 30 字，canonical 正式網域；專輯頁的合集內連在整頁快取裡（爬蟲看得到）；被標在合集裡的系列也算「有收藏」，收錄判斷跟著放寬

### 照片標記做到哪個程度

**清單＋照片上點位置都做了**。清單是必填，位置選填：按那一列「標在照片上」，照片外框變黑、上方黏一條「點照片上 3 號的位置」，手指點一下就放；可以「改位置」「拿掉位置」，清單可以 ↑ ↓ 排順序。合集頁上號碼是 24px 黑底白字方塊（點的範圍 36px），點號碼清單那列反白。手機評估：WebKit 390 3x 用觸控點 4 個位置，號碼落點誤差 0.2%（< 2%）；號碼會蓋住一小塊照片，專輯擺很密的合照（一張 CD 小於 36px）在手機上會點不準，這種情況靠清單。沒做拖曳移動號碼、也沒做放大照片再標。
