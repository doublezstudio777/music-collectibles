## 1. 首頁藝人圓圈列

- 位置：標語下面、排序分頁籤上面，登入與否、有沒有追蹤都出現
- 一排最多 24 位，第 25 格「全部藝人」（空心圓加箭頭）連到 `/artists`
- 桌機圓圈 64px、每格 80px，1136px 寬放得下 12 位半，第 13 位露出一截，看得出右邊還有；超出可以左右滑（桌機有細捲軸）。手機每格 76px，右側出血到螢幕邊緣、scroll-snap、滑到底留空白（同系列卡片）
- 排序：伺服器輸出依收藏數多到少、同數依名稱（`zh-Hant`）；已追蹤的藝人等 `/api/me` 讀進來，在瀏覽器端移到最前。整頁快取的 HTML 不因人而異，伺服器最多給 60 位讓瀏覽器挑
- 圓圈照片：`Catalog.artistFaces()`，藝人使用中照片 → 相關收藏（跟誰有關或標籤撞名）最新一則沒被鎖定的縮圖（浮水印已燒進檔）→ 灰底 `--surface2` 加名字第一個字。沒有用官方封面。藝人照片 `object-position: 50% 22%`（直幅半身照，臉在上方）
- 快取：藝人使用中照片併進目錄的同一批查詢（`content.ts` 的 `db.batch` 多一句，只在目錄重建時跑）；`artist_photos` 的觸發器本來就只在「使用中」變動時加內容版本號。圓圈列只用收藏數，不用讚數與留言，按讚、留言不會讓整頁快取失效
- 拿掉「熱門藝人」三欄文字區塊（`HotArtists`、`Catalog.hotArtists`、`.hot*` CSS）
- 追蹤：藝人頁標題旁本來就有追蹤按鈕（`app/artist/[artist]/page.tsx` 的 `FollowButton`），確認過
- **不感興趣**：只存在首頁熱門藝人，照建議直接拿掉入口。`artist_dismissals` 表、`/api/me/dismissals`、`dismissArtist` 都保留沒動。圓圈列不看這份名單：入口拿掉後使用者沒辦法取消，繼續濾會讓那位藝人永遠消失

## 2. /artists 圓圈格狀

- 每位一個圓圈（同上優先序），下面名字、「N 則收藏」。桌機一排 6（圓圈 112px）、1000px 以下一排 4、700px 以下一排 3（圓圈 88px，360 寬每格約 100px）
- 篩選改成首頁排序那一套分頁籤（`.filter`，當前項 2px 橘底線），左邊男歌手／女歌手／團體、右邊國內／國外，再點一次取消。沒有另外加「全部」：兩組各一個「全部」擺同一列反而分不清
- 追蹤按鈕拿掉，追蹤到藝人頁操作
- 順序跟首頁圓圈一樣（收藏數→名稱）。`/api/artists` 輸出欄位不變，順序跟著變成收藏數排序
