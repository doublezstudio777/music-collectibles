# 客製化網站開發安排

**日期**：2026-09-20  
**產品方向**：手機優先的響應式 Web App，先驗證版本資料、收藏與貢獻流程，再擴充交易。

**私人測試站**：https://taiwan-music-collectibles.zukayc.chatgpt.site

## 一、技術基線

- **前端**：React、TypeScript、Vinext／Next 相容路由、Tailwind CSS。
- **部署目標**：Cloudflare Workers 相容環境。
- **資料層**：第一個畫面切片使用示範資料；下一階段才接持久化資料庫。
- **圖片**：先用原創虛構素材驗證版面；正式商品圖必須依圖片授權政策處理。
- **架構原則**：作品、版本與個人收藏狀態分離，未來原生 App 可沿用相同 API 與資料庫。

## 二、第一個製作切片（已完成）

- 版本目錄與關鍵字搜尋。
- 預設「收藏分享」動態，依收藏、想要清單與關注提供可解釋的內容推薦；完整版本目錄是第二入口。
- CD、黑膠、卡帶及影像格式篩選。
- 版本清單與詳細資料同步切換。
- 「我有這個版本」與「加入想要清單」互動。
- 找不到版本時的候選版本入口。
- 手機與桌機響應式版面。
- 原創虛構收藏素材與網站圖示。

目前互動只存在瀏覽器記憶體，重新整理會還原。這是刻意的：先確認介面方向，再導入帳號與資料庫。

新使用者尚無收藏訊號時，不應顯示假個人化內容。正式版先請使用者選擇少量音樂人與偏好格式，再混入受邀收藏者的優質分享；回訪後才逐步以實際收藏、關注與想要行為取代初始偏好。

內容冷啟動先採邀請制：主動邀請少量收藏者各分享一件「有故事、難辨認或正在尋找」的收藏。平台協助把分享連到正確版本，收藏者不必先完成完整建檔。

## 三、下一階段工作拆解

### A. 真實資料模型與種子資料

- 將 20 件收藏測試結果轉成正式欄位。
- 建立音樂人、作品、發行版本及個人收藏四層 schema。
- 製作版本識別碼與修改紀錄規則。
- 匯入經確認的種子資料，不把目前示範資料當正式內容。

### B. 帳號與個人收藏

- 登入與登出。
- 我有、想要、曾擁有狀態持久化。
- 個人收藏頁與公開範圍。
- 帳號刪除及資料匯出基礎流程。

### C. 資料貢獻

- 新增候選版本表單。
- 相似版本提醒，降低重複建檔。
- 待確認、已初步確認、已確認及有爭議狀態。
- 修訂紀錄、資料來源及審核後台。

### C-1. AI 拍照輔助建檔與 MCP

- 將功能放在「分享收藏」流程內：拍攝封面、封底、條碼、目錄號與版權字樣，AI 同時產生分享草稿與版本辨識草稿。
- AI 只提出候選值，不直接建立已確認版本；每個欄位保存信心程度、照片依據及使用者修正。
- MCP 是 AI 與平台資料之間的橋樑，不是辨識模型本身。第一版提供：搜尋相似版本、建立待確認草稿、更新草稿欄位、送出候選版本。
- 寫入動作必須由使用者確認；先搜尋相似版本，避免每次拍照都新增重複條目。
- 使用者若在支援圖片與 MCP 的 AI 工具內操作，可由該工具理解照片後呼叫平台 MCP；但額度、方案限制與圖片支援由各個 AI 端決定，平台不可宣稱一定使用使用者既有額度。
- 若照片直接上傳網站並由網站呼叫模型 API，辨識費用由平台承擔，且需另行處理 API 金鑰、圖片保存、刪除與隱私同意。第一階段不採此方案。
- 辨識失敗時保留一般表單，且不得把 AI 結果描述成真偽鑑定。

### D. 圖片

- 實拍上傳、尺寸限制與壓縮。
- 私人收藏照、公開收藏照及資料庫貢獻照權限。
- 移除 EXIF、檢舉及通知下架紀錄。
- 正式公開前完成圖片授權條款與律師審閱。
- AI 分析用途與公開展示用途分開同意；原始照片的保存期限與刪除機制需明確。

### E. 測試與可觀察性

- 手機與桌機主要瀏覽器測試。
- 搜尋、版本選擇與收藏流程的可用性測試。
- 記錄搜尋無結果、版本辨認時間及建檔中斷點。
- 基本錯誤紀錄、備份與資料還原演練。

### F. 推薦基礎

- 第一版採規則推薦，不先訓練 AI 模型。
- 訊號優先順序：已收藏版本、想要清單、追蹤音樂人、偏好格式、使用者明確略過。
- 每筆推薦顯示原因，並允許降低同類內容。
- 不把價格漲幅、精確願望人數或高價稀有度當主要排序訊號，避免助長炒價。
- 新使用者用明確偏好與編輯精選建立起始內容，不宣稱已理解個人喜好。

## 四、暫緩功能

- 站內金流、平台代收代付及超商物流。
- 完整私訊系統。
- 原生 iOS／Android App。
- 收藏總價、稀有度排行或價格漲幅榜。
- 全品類周邊欄位；先完成音樂載體核心模型。

## 五、開始開發前仍需使用者決定

這些選擇會影響正式資料與帳號設計，但不阻礙目前介面原型：

1. 第一個真實資料範圍：單一音樂人、10 組音樂人，或先限 CD／黑膠。
2. 網站正式名稱；目前工作名稱為「留聲冊」。
3. 第一批測試者是否需要登入，或先使用邀請碼進入。
4. 收藏頁預設為私人，還是由使用者逐筆設定公開。

## 六、建議的下一個工程里程碑

完成 20 件收藏實測後，將真實欄位導入資料庫，讓第一批受邀測試者可以登入、搜尋版本並保存「我有／想要」。接著先做一般候選版本表單，再把同一份草稿 API 開放給 MCP 使用；如此即使 AI 端暫時不可用，網站流程仍能獨立運作。交易功能不進入這個里程碑。
