## 決策

| 項目 | 決定 | 取代 |
|---|---|---|
| 分享動作命名 | 「炫收藏」 | Codex 稿「分享我的收藏」 |
| 互動 | 「點讚」 | 與「儲存這篇」的關係**待確認**（見下） |
| 標籤點擊去向 | 列出所有人分享中帶這個標籤的收藏 | Codex 稿的全站／個人範圍未定 |
| 物件類型 | 不預設固定類別，使用者可自由填「這是什麼東西」 | 「非音樂載體是否另設商品系列層與類別專屬欄位」 |
| 物件關係 | 用標籤標「跟誰有關」，涵蓋印有名字、照片、本人簽名等情形 | 場刊名單列名等另作物件關係的構想 |
| 分享最低輸入 | 必填：是什麼東西＋跟誰有關 | — |
| 網站副標 | 「音藏｜樂迷的收藏分享」 | 暫用的「音藏」 |
| 版本差異對照 | 多欄並排 | 一次比兩個 |
| 作品頁正文 | 任何人都能寫 | 編輯預寫／留空 |
| 網址識別碼 | 藝人用本人藝名或音譯，有英文名用英文名；作品用流水號，掛在藝人底下 | 羅馬拼音／中文／流水號三選一 |

## 仍需確認

1. **點讚與儲存**：點讚是取代「儲存這篇（留著以後看）」，還是另外多一個公開按讚、儲存照留？
2. **標籤與正式分類的界線**：Codex 稿的規則是「單純加標籤不能更改歌手作品表或產生獎項認證」。使用者的決定跟這條不衝突：標了某歌手，收藏會出現在該歌手頁的「相關收藏」，不會變成他的專輯。沿用，除非使用者另有指示。
3. **任何人都能寫作品頁**：施工時需要修改紀錄與回復機制，否則一次惡意編輯就蓋掉內容。屬實作細節，不影響本決策。
4. **網址形狀**：藝人識別碼加作品流水號，路由可能從 `/work/[work]` 改為 `/artist/[artist]/[流水號]`，施工時定。合輯、多位藝人共同作品掛在誰底下待定。

## 追加定案（2026-09-24）

> A取代儲存 點讚就是可以自己看自己喜愛清單
> 任何人都可以寫該藝人的作品頁面 都要有紀錄 可以向維基百科那樣留名是誰提供的
> 多位藝人或合輯就看發行的是誰啊

- **點讚取代「儲存這篇」**：點讚＝留著以後看，自己可以看自己的喜愛清單。原本的「儲存」按鈕與「已儲存」分區改名為點讚／喜愛清單；點讚仍不代表持有，與「我有」「想要」「炫收藏」分開
- **作品頁像維基百科**：任何人可編輯，每次修改留紀錄並署名提供者（編輯歷史＋貢獻者名單），可還原
- **多位藝人作品與合輯**：掛在發行方底下（發行的藝人或唱片公司／主辦單位）。參與的其他藝人用標籤與關係連過去，出現在他們頁面的相關作品，不算他們自己的專輯

## 帳號定案（2026-09-24）

> 1.第一階段我們就先EMAIL就好
> 2.開放

- **登入方式**：第一階段只做 Email。Google、LINE 等社群登入之後再加。密碼登入或寄登入連結（免密碼）施工時再定
- **註冊**：開放所有人註冊，不用邀請碼
- **排序**：作品頁的維基式署名和炫收藏都需要帳號，所以帳號不會排在最後，會跟這兩個功能一起做
- **開放註冊的配套**（施工時處理）：擋機器人註冊、作品頁編輯可以還原、有檢舉管道

## 平台定位與收入路線（2026-09-26）

> 好 那就先做撮合 然後出價開價這些都可以 不過下一步就是他們自己去約面交 各自交易
> 目前現階段我都是只做媒合平台 但我印象中不是有那種可以贊助咖啡的工具 我覺得也是要開 如果你喜歡的話可以贊助我喝咖啡之類
> 然後資料數據變多 變大之後 在考慮要不要有交易功能 以及開始賣給官方之類的
> 然後我不排除也是有真的唱片行在上面掛賣東西 前期就都免費 或許是要申請某個認證可能可以要付費之類的 像這東西雖然我都有主機網域 但還是要有一些費用回收才對吧?

- **交易模式定案：撮合**。三狀態（純分享／開放出價／定價出售）、出價公開、賣家可拒絕、成交標已售出；之後買賣雙方自行約面交或轉帳，**錢貨不經過平台**
- 平台自己收代收款需電子支付執照（股份有限公司、實收資本額至少 1 億），排除；未來要做交易走有執照的第三方金流，前提是成立公司行號並確認金流商有平台多賣家方案
- **現階段開「贊助」入口**（請站長喝咖啡），工具待選
- **收入路線**（依序，後面的都等資料與使用量起來再說）：
  1. 贊助（現在）
  2. 認證店家：實體唱片行可上架，前期免費；之後「認證店家」標章或進階功能可能收費
  3. 交易功能：資料與交易量變大後再評估，走第三方金流
  4. 賣給官方：官方商品販售、數據洞察（原企劃書路線）
