# 組織與開發流程圖：討論紀錄

**日期**：2026-09-30

**使用者問題**：在產品與商業模式執行版補篇後，希望看到組織架構圖和開發流程圖。

## 決策與理由

- 圖以目前已存在的一人專案加兩台 AI 協作為準：站長負責方向、預算及對外責任；Mac Codex 支援企劃研究；Windows Claude Code 是現階段主要施工及部署端。AI 是工作支援，不能畫成已雇用的公司部門。
- 樂迷、律師、店家與發行方是參與者或未來協力對象；沒有證據顯示已有付費店家、合作合約或正式顧問職位。未來可能補的職能用「工作量觸發」表述，不先畫虛構團隊。
- 開發流程從真實使用問題開始，先判斷現有功能是否足夠，再走企劃、實作、驗收、部署、觀察。加入共用規則規定的 pull／交接／push；舊首次部署手冊與目前已上線狀態分開。

## 沒有採用

- 沒畫 CEO、CTO、行銷、客服等固定職稱編制，因為目前沒有那些受雇人員。
- 沒把任何新需求直接接到「開發」：9/30 執行版已把真實使用與資料可信度設為下一段優先事項。
- 沒把每次部署寫成必須重問使用者一次；按既有授權與變更範圍判斷，產品方向仍由站長決定。

## 未解問題

站長實際每週可投入的營運時間、招募進度、外部律師及店家合作時點仍待真實工作量和合作意願確認。圖若隨角色或部署流程變化，需要再更新，避免繼續使用過時組織圖。
